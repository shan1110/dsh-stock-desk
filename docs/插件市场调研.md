# DSH 插件市场：机制、格式与把本插件上架的步骤

> 调研时间：2026-10-20
> 环境：DSH 0.2.1-rc.2，profile `desktop`，Web GUI `http://127.0.0.1:8820`
> 结论分两级：**已验证**（跑过命令/读过源码）与**推测**（未实测）。不要把推测当结论用。

## 0. 一句话结论

DSH **没有**公共的第三方插件市场。所谓「市场」是：一个默认关闭的实验性 bundle，读取**用户自己配置的 http(s) 索引 URL**，把索引里的 bundle 列出来供安装。

本插件当前用 `install_bundle` 直接从 `E:\dsh-plugin` 装进 profile（`source: "link:E:\dsh-plugin"`），
改代码重载即生效。**上市场对本项目是净负担**：每次改代码都要重新发布并更新索引里的版本号/commit SHA，
才能让市场里的版本跟上，而开发期间一天可能改十几轮。所以当前决策是不上市场。

本文留档，供以后真需要分发时使用。

## 1. 市场机制（已验证）

### 1.1 市场不是内置的

`plugin_manager` 的 `list_bundles` 输出里，唯一相关条目：

```
name        @deepseek-ai/dsh-experimental-plugin-market-bundle
official    true
enabled     false
availability installation
description Experimental custom plugin markets: a Discover tab that browses and installs
            bundles from plugin market indexes
```

`official: true` 的其余条目全部是 `@deepseek-ai/*` 官方包，没有第三方来源。
`availability: "installation"` 且没有 `installTarget` 字段 → 随 DSH 安装一起提供，
启用方式是 `set_bundle`，不是 `install_bundle`：

```
plugin_manager action=set_bundle target=@deepseek-ai/dsh-experimental-plugin-market-bundle enabled=true
```

启用后新增两样东西：Web 设置里的「发现」标签页，以及 `plugin_market` agent 工具。

### 1.2 索引源默认是空的

`@deepseek-ai/dsh-plugin-market` 的 `Config`（`lib/types/index.d.ts`）：

| 配置 | 默认值 | 含义 |
|---|---|---|
| `indexes` | `[]` | 按显示顺序排列的索引 URL |
| `fetchTimeoutMs` | `15000` | 单次索引获取时限 |
| `maxBytes` | `134217728` | 索引响应体上限 |
| `cacheTtlMs` | `600000` | 成功读取的缓存时长 |

`indexes` 为空时**一个请求都不发**。所以市场装了不配源，什么也不会发生。

### 1.3 索引 URL 与安装源的限制（已验证）

索引 URL（`lib/types/index-url.d.ts` 的 `normalizeIndexUrl`）：必须是 http(s)，不含凭据或片段，
**拒绝重定向**（只能经重定向访问的索引必须直接配最终 URL）。

安装源（`@deepseek-ai/dsh-plugin-market-index` 的 `MarketSource`，`lib/types/types.d.ts:37-49`）
只有两种：`npm` 与 `git`。**没有 `link` / `file` / 本地目录**。

## 2. 索引格式（已验证）

`format: 1` 的 JSON 文档。用官方校验器 `parseMarketIndex` 实跑过，下列样例**通过校验**。

### 2.1 已通过的样例

```json
{
  "format": 1,
  "title": { "zh": "行情插件集市", "en": "Quote market" },
  "description": { "zh": "自用插件", "en": "Private" },
  "metadata": {
    "categories": { "finance": { "title": { "zh": "行情", "en": "Market data" } } },
    "labels": { "a-share": { "title": { "zh": "A股", "en": "A-shares" } } },
    "sortKeys": { "stars": { "title": { "zh": "星标", "en": "Stars" }, "order": "desc" } }
  },
  "plugins": [{
    "name": "dsh-stock-desk",
    "title": { "zh": "A股行情工作台", "en": "A-share desk" },
    "description": { "zh": "整页看盘", "en": "Full page" },
    "author": "cai shan",
    "metadata": {
      "category": "finance",
      "keywords": ["stock", "行情"],
      "labels": ["a-share"],
      "sortKeys": { "stars": 1 }
    },
    "versions": [{
      "version": "2026.10.20",
      "publishTimestamp": 1792000000,
      "source": {
        "type": "git",
        "url": "https://github.com/example/dsh-stock-desk",
        "commit": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
      },
      "engines": { "dsh": ">=0.2.1-rc.2" }
    }]
  }]
}
```

### 2.2 容易踩的字段规则

- `title` 是 `LocalizedText`，**必须含 `en`**。实测：`{zh:"行情"}` 报 `must contain en`；
  纯字符串 `"行情插件集市"` 反而被接受。稳妥写法是 `{en, zh}`。
- `versions` 按 SemVer 优先级**降序**排列，且非空。
- `category` / `labels` / `sortKeys` 里出现的 id，必须在上层 `metadata` 里声明过，
  否则不匹配任何插件。
- `publishTimestamp` 是 **Unix 秒**，不是毫秒。
- 校验通过后会丢弃格式未定义的成员、补空 `keywords`/`labels`/`sortKeys`/`engines`、
  把相对 `icon` 解析成绝对 URL。

### 2.3 安装串是这样拼出来的

`lib/index.js` 的 `marketInstallTarget`：

- npm → `name@version`，该版本声明了 `registry` 时附带 registry
- git → `git+<url>.git#<commit>`，有 `path` 时追加 `&path:/<path>`

实测各 source 变体的接受情况：

| 写入的 source | 结果 | 生成的 spec |
|---|---|---|
| `{type:'npm'}` | ✓ | `dsh-stock-desk@2026.10.20` |
| `{type:'npm', registry:'https://registry.npmmirror.com'}` | ✓ | `dsh-stock-desk@2026.10.20` + registry |
| `{type:'npm', registry:'http://127.0.0.1:4873'}` | ✓ | 同上（本机私有源可以） |
| `{type:'npm', registry:'https://user:pw@host'}` | ✗ | `must not contain credentials` |
| `{type:'git', url:'https://github.com/u/r', commit:'<40位>'}` | ✓ | `git+https://github.com/u/r.git#<40位>` |
| `{type:'git', url:'http://192.168.1.5/u/r', ...}` | ✗ | `must use https:` |
| `{type:'git', url:'file:///E:/dsh-plugin', ...}` | ✗ | `must use https:` |
| `{type:'git', url:'ssh://git@github.com/u/r', ...}` | ✗ | `must use https:` |
| `{type:'git', commit:'abc1234'}` | ✗ | `must be a lowercase 40-hex-digit commit SHA` |
| `{type:'link', path:'E:/dsh-plugin'}` | ✗ | `must be "npm" or "git"` |
| `{type:'file', path:'E:/dsh-plugin'}` | ✗ | `must be "npm" or "git"` |

**关键推论**：本地目录任何形式都进不了市场。想让市场里的条目能被真正安装，
必须先发布到公网 npm、或公网 https git、或本机运行的私有 npm registry。

### 2.4 「已安装」状态不看源

安装状态按**包名**与 `pluginManager.listBundles()` 比对，与 source 是否可达无关。
本插件已以 `link:` 方式装了 `dsh-stock-desk@0.1.0`（后改为 `2026.10.20`），所以索引里只要有同名同版本的条目，
发现页就会显示「已安装」——即使在别的机器上点安装会失败。

## 3. 三条上架路线

| 路线 | source 写法 | 前置条件 | 每次改代码的代价 |
|---|---|---|---|
| 公网 npm | `{type:'npm'}` | npm 账号；去掉 `private: true` | `npm version` + `npm publish` + 改索引版本号 |
| 私有 npm（本机 Verdaccio） | `{type:'npm', registry:'http://127.0.0.1:4873'}` | 本机跑 Verdaccio | `npm publish --registry ...` + 改版本号 |
| 公网 https git | `{type:'git', url, commit}` | GitHub/Gitee 仓库 | commit + push + 改索引里的 40 位 SHA |

### 3.1 前置条件：当时的缺口与现在的状态

本节最初写于 2026-10-19，那时三条都不满足。现已全部补齐，保留原文以便对照：

| 当时的缺口 | 现在 |
| --- | --- |
| `E:\dsh-plugin` 不是 git 仓库 | 已是仓库，推到 `github.com/shan1110/dsh-stock-desk`（public，MIT） |
| `package.json` 里 `private: true`、`license: UNLICENSED`、无 `repository` | 三者都已改正：无 `private`、`license: MIT`、有 `repository`/`homepage`/`bugs` |
| 没有发布到任何 registry | **已发布 `dsh-stock-desk@2026.10.20`**（2026-10-20 09:03Z，npm 官方源，`latest` 指向它） |

**但市场仍然没上**，理由不变（见开头）：上市场要维护一份索引 URL 并跟着改版本号，
而开发期一天改十几轮，净负担。发布 npm 与上市场是两件事：
前者让别人能 `install_bundle`，后者让别人能「发现」它。

发布 npm 时踩到的两个坑，记在这里免得下次重来：

1. **`20261020` 这种纯日期串不是合法 semver**，`npm publish` 直接拒。要用 `2026.10.20`（三段式）。
2. **带写权限的 granular token 默认 `bypass_2fa: false`**，而 2FA 关闭的账号必须先满足
   「开 2FA」或「token 勾 Bypass 2FA」之一，否则永远 403，且报错文案两句话里只有第一句有用。
   发之前用 `npm token list --json --registry https://registry.npmjs.org` 确认 `bypass_2fa` 为 `true`，
   比发布失败后再猜快得多。
3. 发布成功那一刻 registry 上先出现一个 `0.0.0-stage` 占位版本（描述写着
   `Temporary package placeholder for staged publishing`），约 20 秒后真实版本才入库。
   **看到它别慌，那不是别人抢注。**

### 3.2 真要走 git 路线时的步骤

1. `git init`，写 `.gitignore`（至少要排除 `node_modules`、`data/universe.json` 视策略而定）
2. 推到 GitHub/Gitee，拿到仓库地址
3. 取完整 commit：`git rev-parse HEAD`（必须 40 位小写 hex）
4. 写索引 JSON（见 §2.1），`source.url` 填仓库地址、`commit` 填上一步的值
5. 把索引 JSON 托管到 **http(s)** 上（GitHub Pages / Gitee Pages / 本机静态服务器均可，注意不接受重定向）
6. 启用市场 bundle（见 §1.1）
7. 设置 → 发现 → 添加索引 URL，或 `pluginMarket.setIndexes([...])`

### 3.3 「全本地」组合是否可行

索引允许 http、npm registry 允许 http 本机地址 —— 两条都是**已验证的 schema 层结论**。
但「Verdaccio + `install_bundle` 真实装上」**没有实测**，属于**推测可行**。
真要采用，第一步应当是先跑通一次真实安装，再写索引。

## 6. 发布到公网 npm 的清单

不开市场也能让别人装 —— 包发到公网 npm 就行。这一节是给「真要让别人用」准备的。

### 6.1 已改好（2026-10-20）

| 改动 | 原因 |
|---|---|
| 去掉 `"private": true` | 留着它 `npm publish` 直接拒绝 |
| `"license": "UNLICENSED"` → `"MIT"` | `UNLICENSED` 意味着别人法律上不能用；MIT 与已上架的 `dsh-trellis` 一致 |
| 新增 `LICENSE` 文件（MIT） | 只写字段不够，仓库里要有正文 |
| 新增 `keywords`（8 个） | `npm search` 与市场索引的文本匹配都读它 |
| README 增加「安装（使用者）」段 | 原来整篇是给作者自己看的，使用者不知道怎么装 |

### 6.2 剩下的两步（需要你的账号）

**注意 registry 陷阱。** 这台机器的 `.npmrc` 是：

```
registry=https://registry.npmmirror.com
```

npmmirror 是**只读镜像，不能发布**。发布时必须显式指定官方源：

```powershell
npm login --registry https://registry.npmjs.org
npm publish --registry https://registry.npmjs.org
```

否则报的错会像「网络问题」，实际是往镜像源推包。

`dsh-stock-desk` 这个包名实测在公网 npm 上未被占用（`npm view dsh-stock-desk` 返回 404）。

### 6.3 发布后别人怎么装

```powershell
plugin_manager(action: install_bundle, target: "dsh-stock-desk@2026.10.20")

# 或
dsh plugin --profile <profile> add dsh-stock-desk@2026.10.20
```

装完刷新页面，侧边栏出现行情台图标。

### 6.4 后续每次发版

> 下文示例里的版本号是 `2026.10.20`（首个发包版本）。**当前 `latest` 是 `0.1.1`**：
> 日期式编号在同一天要出第二个版本时没有位置（四段式不合法、`-1` 预发布又抢不到 `latest`），
> 所以改用普通 semver。代价是 `0.1.1` 在排序上小于 `2026.10.20`，依赖范围会割裂，
> 但 `npm i` 默认装 `latest`，不受影响。

npm 不允许覆盖已发布的版本号。改完代码要：

```powershell
npm version patch --no-git-tag-version   # 2026.10.20 -> 2026.10.21
npm publish --registry https://registry.npmjs.org
```

别人装新版本用新的版本号；已有的旧版本不会自动更新（市场 README 明确写了「不支持升级」，
索引里报 `update-available`，仍需卸载再装）。

### 6.5 还没做的

- **`repository` 字段已补。** 2026-10-20 仓库建立在 <https://github.com/shan1110/dsh-stock-desk>，
  `package.json` 中 `repository` / `homepage` / `bugs` 三个字段都已填。
- **没有市场索引。** 想要「发现页可见」才需要，见 §1–§3。纯 npm 分发不需要。
- **`engines.dsh` 没声明。** 官方包（如 `@deepseek-ai/dsh-plugin-market`）的 `package.json` 里
  也不声明 `engines`，所以照惯例留空；市场索引的每个版本另外声明 `engines.dsh`。

### 6.6 版本管理：GitHub 仓库

远端：`git@github.com:shan1110/dsh-stock-desk.git`（公开）
首个提交：`ceac6bb`，48 个文件，1.0 MB

仓库级配置（只作用于本仓库，未改全局 `~/.gitconfig`）：

| 配置 | 值 | 原因 |
|---|---|---|
| `core.quotepath` | `false` | 本仓库 5 篇文档是中文名，不关掉 `git status` 显示成 `\344\270\234` 八进制 |
| `core.autocrlf` | `false` | 配合 `.gitattributes` 的 `* text=auto eol=lf`，仓库内统一 LF |
| `user.email` | `<个人邮箱>` | 用户指定；全局仍是另一个工作邮箱，未改动（地址已隐去，避免随仓库公开） |

`.gitignore` 排除的四项及理由：

1. `node_modules/` —— 其中 `@deepseek-ai` 是指向 DSH profile 的 **Junction**，Git 无法表达
2. `.backup/` —— 上一版插件 dsh-stock-watch 的备份，1.4 MB
3. `.preserved-skills/` —— 第三方 skill，含他人的 LICENSE.txt，不随本仓库分发
4. `tools/.last-client.txt` —— 探针脚本的临时输出

认证方式：SSH 密钥 `~/.ssh/id_ed25519`（**无口令**）。HTTPS 走不通，因为
Git Credential Manager 需要交互式终端，非交互 shell 里报
`bash: /dev/tty: No such device or address` 而失败。

### 6.7 一处需要你确认的既存事实

`lib/eastmoney.js` 仍在包内，且 `lib/market.js` 里 `rawKlineEm` 仍作为**分钟线 K 线的兜底源**
被调用（注释原文：「先试腾讯，它不支持或失败再退东财」）。README 里也照实写了。

这与「东财整个不考虑」的印象不一致 —— 当初排除东财是针对**板块**（`lib/boards.js`
头部注释记录：东财 push2 的 `clist/get`、`kline/get` 被按路径拦截，板块榜与成分股取不到）。
如果分钟线也要彻底去掉东财，需要另改 `lib/market.js` 的 `rawKline` 回退链，
并在 `docs/` 里记一次，避免下次又当成没发生。
