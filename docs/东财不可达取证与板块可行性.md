# 东财「不可达」的取证与板块功能可行性

> 时间 2026-10-19 16:12 · 结论全部来自可复现命令，分「已验证 / 未验证」标注。

## 1. 结论先说

**不是没有免费接口，也不是网络断了。是东方财富对「榜单类批量接口」做了针对性拦截（反爬），
同一个域名下单只查询类接口照常返回 200。**

最可能的原因：今天插件与探测脚本高频调用了这两个批量接口，触发了限流 / 临时拉黑。
**推测成分**：无法证实，只能说现象与该解释一致。

## 2. 分层取证

### 2.1 网络层全部正常（已验证）

| 检查 | 命令 | 结果 |
|---|---|---|
| DNS | `Resolve-DnsName push2.eastmoney.com` | `61.129.129.196` ✓ |
| TCP 443 | `Test-NetConnection push2.eastmoney.com -Port 443` | `TcpTestSucceeded=True` ✓ |
| TLS 握手 | `curl -sv` | `ALPN: server accepted http/1.1` → `Connected` → 请求发出 ✓ |
| 对照 | `qt.gtimg.cn` / `data.10jqka.com.cn` | 均 200 ✓ |

即：TCP 连得上、TLS 握手成功、HTTP 请求发出去了，**然后一个响应字节都收不到**：

```
* Connected to push2.eastmoney.com (47.112.165.11) port 443
> GET /api/qt/clist/get?... HTTP/1.1
* closing connection #0
```

curl 退出码 **56**（`CURLE_RECV_ERROR`）。

### 2.2 不是代理问题（已验证）

本机系统代理是开着的，但 **Node 的 fetch(undici) 默认不走 Windows 系统代理**，浏览器走、脚本直连。
所以专门区分过：

| 路径 | 结果 |
|---|---|
| 直连 东财首页 | **200** 58720B ✓ |
| 直连 东财 API | 000 退出码 56 ✗ |
| **`curl -x http://127.0.0.1:7890` 走代理打同一个 API** | 000 退出码 56 ✗ |

**走不走代理都一样** —— 排除代理因素。代理仅用于本条诊断，**已撤**。

（环境变量里没有任何 `*_PROXY`；`ProxyEnable=1 ProxyServer=127.0.0.1:7890` 在注册表里。）

### 2.3 是路径级拦截，不是域名级封禁（已验证 · 决定性）

同一个 `push2.eastmoney.com`：

| 路径 | 结果 |
|---|---|
| `/api/qt/stock/get` | **200** 127B ✓ |
| `/api/qt/ulist.np/get` | **200** 159B ✓ |
| `/api/qt/clist/get` | 000 · 56 ✗ |
| `/api/qt/stock/kline/get` | 000 · 56 ✗ |
| `push2his.eastmoney.com/...kline/get` | 000 · 56 ✗ |

**`clist/get` 是参数无关地被掐** —— 逐个加参数、从裸的 `?pn=1&pz=2` 到完整板块查询，
**8 种变体全部 56**；`fs` 用字面 `+` 还是 `%2B` 编码也一样。
加 `Referer` / `Origin` / `Cookie` 也全部一样。

而**同一域名的静态页面完全正常**：

| 页面 | 结果 |
|---|---|
| `https://quote.eastmoney.com/` | 200 58720B ✓ |
| `https://quote.eastmoney.com/center/boardlist.html` | 200 20965B ✓ |
| `https://data.eastmoney.com/bkzj/hy.html` | 200 208205B ✓ |
| `https://data.eastmoney.com/bkzj/BK0546.html` | 200 216316B ✓ |

**「首页能通、榜单接口不通」是反爬的典型形态，不是接口下线。**
免费接口依然存在，路径也用对了（`clist/get` 就是官方在用的那个）。

## 3. 绕行方案（已实测）

被掐的是 `clist/get` 和 `kline/get` 两个批量接口，但**取数不是只有这一条路**：

| 要的东西 | 绕法 | 实测 |
|---|---|---|
| 全部板块代码 + 名称 | `data.eastmoney.com/bkzj/hy.html` 里是服务端渲染的锚点：`<a href="/bkzj/BK0546.html">玻璃玻纤</a>` | ✓ **675 个**，正则可取 |
| 板块行情（涨跌幅等） | `push2.eastmoney.com/api/qt/ulist.np/get?secids=90.BK0475,90.BK0917&fields=f12,f14,f3,...` | ✓ **200**，返回 `{"f3":1.55,"f12":"BK0475","f14":"银…"}` |
| 板块涨停家数 | 同花顺 `dataapi/limit_up/block_top` → `limit_up_num` | ✓ 20 个板块，见 §4 |
| **板块全部成分股** | `clist/get?fs=b:BKxxxx` 被掐；`slist/get?secid=90.BK0475` → `rc:102` 空；`bkzj/BK0546.html` 是前端渲染（216KB 里 **0 个股票代码**） | ✗ **暂无可用路径** |

## 4. 同花顺 `block_top` 实测（维度「涨停最多」的数据源）

- **硬编码只返回 20 个板块**，`page` / `limit` 参数被忽略（传 100 仍是 20）
- 板块字段：`code` `name` `change` `limit_up_num` `continuous_plate_num` `high` `days` `stock_list`
- **没有 `limit_down_num`** —— 所以「跌停最多的板块」没有数据源
- `stock_list` 长度恰好等于 `limit_up_num`（机器人概念 18 = 18）
  → **它给的是「该板块今日涨停的个股」，不是板块全部成分股**

同花顺 dataapi 路径探测（10 个候选名）：只有 `limit_up_pool` 和 `open_limit_pool`（炸板）存在，
`limit_down_pool` / `down_limit_pool` / `limit_down` / `down_pool` / `limit_down_list` /
`limit_up_down_pool` / `block_limit_down` **全部 404**。

全市场跌停家数**有**（`lib/ths.js:88` `limit_down_count` = 22），但没有板块维度。

### 7.1 路径 5 的细节（唯一出数据的）

`http://q.10jqka.com.cn/gn/detail/code/301558/`（GBK 编码，需 `TextDecoder('gbk')`）
服务端渲染，页面内有：

```html
<h2>成分股涨跌排行榜</h2>
<table class="m-table m-pager-table">
  <th>序号</th><th>代码</th><th>名称</th><th>现价</th>
  <th field="199112" order="desc" class="cur">涨跌幅(%)</th>
  <th>涨跌</th><th>涨速</th><th>换手</th><th>量比</th><th>振幅</th><th>成交额</th>...
```

实测 `301558` = 阿里巴巴概念，`<tbody>` 内 **10 行**，解析结果：

```
["1","301666","大普微","328.51","20.00","54.75","0.00","21.83","2.51","20.51","23.13亿","0.35亿","114.64亿","53.71"]
 序号  代码    名称    现价   涨跌幅  涨跌   涨速   换手   量比   振幅    成交额  ...
```

**默认排序就是涨跌幅降序**（`field="199112" order="desc" class="cur"`），与需求一致。

**但：**
- 每页固定 **10 行**，不是 20
- `?page=2` 被忽略（返回内容与第 1 页**逐字节相同**，len 都是 73452）
- 经典 ajax 形式 `/field/199112/order/desc/page/2/ajax/1/code/301558/` → **HTTP 401**
- 带上首跳 cookie 仍 401；**首跳响应里没有任何 `Set-Cookie`** → 它校验的是 JS 现算的 `hexin-v` 签名，不是会话 cookie

### 7.3 成功路径（第 9 条）：普通路径翻页，不要 `ajax/1`

**401 的真相**：那个 401 页面正文是一个 `chameleon.1.7.min.js` 反爬脚本，它把请求
`window.location.href` 跳转到 ajax URL 自身 —— 也就是**它要求先过 JS 挑战**，
不是缺 cookie、也不是登录。

**绕过方式：完全不碰 `ajax/1` 前缀，改用普通路径把页码放在 `code` 后面。**

```
# 第 N 页（概念板块，10 只/页）
http://q.10jqka.com.cn/gn/detail/code/{301xxx}/page/{N}/

# 第 N 页（行业板块，20 只/页）
http://q.10jqka.com.cn/thshy/detail/code/{881xxx}/page/{N}/
```

实测（GBK 需 `TextDecoder('gbk')`）：

| 请求 | 结果 |
|---|---|
| `/gn/detail/code/301558/page/2/` | **HTTP 200**，`page_info = 2/35`，首行 `300556 丝路视觉` |
| `/gn/detail/code/301558/page/3/` | **HTTP 200**，`page_info = 3/35`，首行 `600580 卧龙电驱` |
| `/gn/detail/code/301558/page/1..3` 合并 | 30 行，**去重后仍 30 只，零重叠** ✓ |
| `/thshy/detail/code/881121/page/1/` | **HTTP 200**，`page_info = 1/10`，**20 行** |
| `/thshy/detail/code/881121/page/2/` | **HTTP 200**，`page_info = 2/10`，**20 行**，首行 `603375 盛景微` |
| `/gn/detail/code/301558/page/35/` | HTTP 200 但 0 行 —— 尾页号可能滞后，取数时按实际返回裁剪 |

**关键差异：概念板块 10 只/页，行业板块 20 只/页。**
需求是「默认 20 只、可翻页」，概念板块拉两页拼成 20 只即可，行业板块原生就是 20。

排序：页面内 `<th field="199112" order="desc" class="cur">涨跌幅(%)</th>`，
**默认即涨跌幅降序**，与需求一致。

## 8. 意外收获：腾讯的板块接口比东财全（已验证）

`https://proxy.finance.qq.com/cgi/cgi-bin/rank/pt/getRank`

| 参数 | 结果 |
|---|---|
| `board_type=hy` | 31 个行业板块 |
| `board_type=gn` | **805 个概念板块** |
| `board_type=dy` | 31 个地域板块 |
| `board_type=all` | **991 个板块，一次拿全** |
| `board_type=hangye` / `gainian` | `code:0` 但 `rank_list:[]`、`total:0`（未知名静默返回空） |

单条板块的完整字段（食品饮料 `pt01801120` 实测）：

| 字段 | 含义 |
|---|---|
| `zdf` | 涨跌幅 ✓ |
| `zgb` | **`"46/122"` 涨跌家数** ✓ |
| `zljlr` / `zljlr_d5` / `zljlr_d20` | 主力净流入（当日 / 5 日 / 20 日） |
| `lzg` | **领涨股 `{code,name,zd,zdf,zxj}`** ✓ |
