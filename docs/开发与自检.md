# 开发与自检

本文承接 [README](../README.md) 的开发与测试两节，记录开发期的约定、自检套件的行为，
以及本项目踩过并且已经固化成断言的坑。

## 1. 改动后的生效路径

| 改了什么 | 要做什么 |
|---|---|
| `client.js`、`locale/*.json` | 重启插件 + **刷新浏览器页面**；客户端模块只在页面加载时取一次 |
| `lib/*.js`、`index.js` | 重启插件 |
| `package.json` 的 `dsh.client` | 重启插件 + 刷新页面，并用 `/diag` 确认 `wired` |

重启插件的动作（HMR 不会热更已激活插件的文件改动）：

```
plugin_manager(set_plugin, target: "include:stock-desk", enabled: false)
plugin_manager(set_plugin, target: "include:stock-desk", enabled: true)
```

改完先问一次客户端半边有没有接进启动图，再去刷新页面：

```powershell
(Invoke-RestMethod http://127.0.0.1:8820/api/stock-desk/diag).data
```

`wired: true` 表示刷新一定有效；`wired: false` 表示刷新多少次都没用，问题在
`package.json` 的 `dsh.client` 声明。两种情况排查方向完全不同，先分辨再动手。

## 2. 自检套件

```powershell
foreach ($t in @("test-tencent","test-sources","test-boards","test-market","test-tools","test-client","test-ocr")) {
  node "tools\$t.mjs"
}
node "tools\test-contract.mjs"    # 需要 GUI 在 http://127.0.0.1:8820 运行
```

全部应退出码 0。

| 套件 | 覆盖 |
|---|---|
| `test-tencent.mjs` | 腾讯字段解析、单位换算、五档盘口形态 |
| `test-sources.mjs` | 多源降级与数据来源标注 |
| `test-boards.mjs` | 板块榜与成分股、免费页数截断 |
| `test-market.mjs` | `/dashboard` 各片段的字段路径与形状 |
| `test-tools.mjs` | 6 个 agent 工具的输出 |
| `test-client.mjs` | 客户端组件的**真渲染**与槽位约定 |
| `test-contract.mjs` | 对运行中的 HTTP 路由逐个核对字段路径 |
| `test-ocr.mjs` | 图片识别的归一化、代码修复、候选匹配，以及一次真实识别 |

### 2.1 时间相关的断言必须写成多态

盘口类断言实测有四种形态：满档 / `null` / 两侧空数组 / 只有买一侧。
写死「一定有买一」会在每天 15:00 后准时变红；更糟的是 `bids[0].price` 会抛 TypeError
把整个套件带崩，连跑了几条都不告诉你。

`test-market.mjs` 与 `test-contract.mjs` 用 `expectData()` 处理：接口在未开盘时返回空，
记为 `SKIP …（未开盘，今天还没有数据）` 并计为通过。`test-boards.mjs` 用 `isClosedNow()`。
收盘状态取自 `/dashboard` 的 `session.trading` —— 注意 `/state` **没有** `session` 字段。

修断言时不要只按这一次看到的形态改。这个坑在本项目里犯了五次。

### 2.2 `test-client.mjs` 是真渲染

它不是构造断言：把 `desk` 喂上一份真实形状的 `/dashboard`，然后调用
`DeskPage()` / `Pill()` / `DeskButton()`，检查渲染出来的文字里到底有没有指数点位、
涨跌幅、涨跌家数。

同一个文件里还包含一条验收标准的机器判定版本：**指数明细不得出现换手率、市盈率、
市净率、涨跌停价、委差、盘口**。它依赖「按字段是否存在渲染」这一设计，不靠肉眼。

### 2.3 桩件验不出来的四类约定

它们的共同点是「框架保证、桩件不校验」，只能在 `test-client.mjs` 里显式断言：

1. 槽位注册的必填字段 —— `shell.overlay` 漏过 `id`，药丸永远不出现且不报错。
2. `sidebar.panellist.id` 必须等于 `main.key` —— 不等则点按钮没反应，同样不报错。
3. `shell.overlay` 整层是 click-through —— 药丸必须自己设 `pointer-events:auto`，
   漏过一次，药丸点不动。
4. 颜色一律走 `--dsw-*` 令牌 —— 写死十六进制切主题不跟随。白名单只留主按钮的 `#fff`。

### 2.4 构建标记

`sidebar.panellist` 的 `order` 刻意取一个不常见的 **77**，作为构建标记。
刷新后用 Slots Inspect 查实时注册表，报出来的正是 77，就说明代码是新的，
可以直接排除「浏览器缓存没刷新」这个可能性。

## 3. 两条硬纪律

1. **`catch` 一律不许静默。** 一个静默的 `catch` 会把「某个组件崩了」变成
   「这一段没渲染」—— 两者症状一样、成因完全不同。
2. **`check` 通过时也要打印。** 否则「一片空白」到底是没渲染还是没打印，一眼分不出来。
   本项目为此白走过三轮。

## 4. `test-contract.mjs` 存在的理由

它逐个核对 `client.js` 读到的每一条字段路径，共 76 条断言，只读、不发 POST。

起因很具体：第 1 轮有 6 处客户端与宿主对不上（`{ok,data}` 信封没拆、`store.path` 不存在、
自选实际取自 `config.groups[].items`），当时没有任何测试真正调过这些路由 ——
全靠手写 PowerShell 探针，而探针本身也写错过好几次（用 `$_.price` 去读嵌套在 `.fields`
里的价格，探针返回空，看起来像插件坏了）。

**断言值一律来自真实响应 dump，不来自记忆。** 拿自己以为的形状当固定装置，
测试会全绿而缺陷照旧。

## 5. `isNotOpenYet` 的适用范围

开盘前（含集合竞价）同花顺会返回业务错误，`status_code` 为 10003，文案形如
`尚未开盘` / `非交易日` / `暂无数据` / `集合竞价`。`lib/ths.js` 的 `isNotOpenYet` 负责识别，
`fetchLadder` 返回 `[]`、`fetchPool` 返回空池。

**注意降级要放在熔断之外。** `lib/cache.js` 的 `SourceHealth` 在连续失败 3 次后抛
`同花顺板块 连续失败 3 次`，而这个异常是在 `fetchBoardStocks` 自己的 try/catch **之外**
抛出的。因此 `lib/market.js` 用 `boardStocksSafe` 包了一层，否则开盘前 `/board` 会 500。

## 6. 时间与预算提示

行情接口自带缓存，页面的刷新间隔设得比 3 秒还短没有意义。
宿主侧 `pollMs` 是服务端缓存周期（当前 3000 ms），客户端的 `ui.pollSec` 是页面刷新间隔（默认 10 秒），
两者是不同概念，不要混用。

## 7. 图片识别的实测记录（2026-10-20）

**动机。** 用户不想为了加一只自选去手打代码，希望直接贴券商截图。

**引擎选择。** 本机可用的是 Windows 自带的 `Windows.Media.Ocr`，`AvailableRecognizerLanguages`
实测为 `["en-US","zh-Hans-CN"]`，中文可用；`tesseract` 未安装。不引入视觉大模型：这条路径不联网、
不上传图片，也就没有把持仓截图发出去的顾虑。

**识别质量（已验证，`tools/fixtures/ocr-light.png` 与深色底同图各跑一次）。**
造两张模拟券商自选截图（浅色底 / 深色底），各 17 行：

| 项 | 结果 |
|---|---|
| 中文股票名 | 4/4 全对（贵州茅台、平安银行、宁德时代、半导体设备ETF） |
| 深色底 | 与浅色底输出完全一致，**不需要反色预处理** |
| 6 位数字 | 会错认：`600519→600S19`、`300750→3007S0`（`5→S`） |
| 中文分词 | 逐字输出带空格：`贵 州 茅 台` |
| 标点 | 全角：`．` `％`；负号 `—` 被认成 `一` |

**结论：以股票名为主、代码为辅。** 名称命中几乎不失误，代码必须先按错认表还原、再落进代码池
才作数。反过来（只信代码）会在数字认错时整只丢掉。

**反向匹配要设歧义阈值。** 券商只显示简称，OCR 得到「半导体设备ETF」而代码池里的全名是
「半导体设备ETF易方达」，正向匹配必然落空，所以加了反向包含。但「半导体设备ETF」同时是
8 只基金的公共前缀，全收进来就是 8 条假候选 —— 实测如此。现在命中超过 3 只整组丢弃。

**PowerShell 桥的三处坑（都实测过）。**
1. PS 5.1 读无 BOM 的 UTF-8 脚本会按系统代码页解码，中文注释直接搞坏语法（报
   `Unexpected token ')'`，行号还指着注释行）。因此脚本走 `-EncodedCommand`（base64 的 UTF-16LE），
   完全不经文件编码 —— 顺带省掉了临时 .ps1 的清理。
2. `AsTask` 的结果类型必须由调用方显式传入。WinRT 对象在 PowerShell 里是 `__ComObject`，
   反射拿不到泛型参数，`MakeGenericMethod` 会收到 null；轮询 `$op.Status` 也永远是空。
3. 结论写 JSON 文件而不是 stdout：中文经控制台代码页会被打乱，且 `stdio:'ignore'` 下读不到 stdout。

**请求体上限要单独放宽。** `lib/routes.js` 的 `MAX_BODY` 是 256 KB，而一张手机截图 base64 之后
轻松过 300 KB。`POST /ocr` 单独用 `MAX_IMAGE_BODY`（8 MB），否则正常截图会被当成异常大包掐断，
报错看起来像「手机截图不支持」。

## 8. 自检框架自身踩过的两个坑（2026-10-20）

**`texts()` 不展开函数组件。** 降级与错误提示都挂在 `Msg` 的 `text` prop 上，而 `texts()` 只沿
`children` / `title` 走，于是「提示文案明明渲染了」在断言里是空的。用 `strings()`（会展开函数组件）。

**`strings()` 遇到回边会栈溢出。** `mountLive` 的 `attachRefs` 把元素的 `props.ref.current` 指回元素
自己，`strings()` 按 `Object.values` 全量下钻就会无限递归，以
`Maximum call stack size exceeded` 收场 —— 这种崩法会把整个文件后续用例一起埋掉。
已在 `strings()` 内部用 `WeakSet` 挡掉。

**直接调 `props.onChange` 不会重渲染。** `rt.dirty` 只在 `mountLive` 的 `click` / `fire` 循环里被消费。
自己 `await setTimeout` 是没用的，必须用新加的 `m.flush()`（排查记录：取消勾选后按钮数字不变，
一开始被当成 `setPick` 没生效）。
