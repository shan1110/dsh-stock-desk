# 安装与激活实测

> 环境：Windows / DSH profile `desktop` / 插件源码 `E:\dsh-plugin`（工作区目录）
> 实测时间：2026-10-19
> 结论标注：**已验证** = 有可复现命令或文件行号；**推测** = 未直接验证

## 1. 工作区目录能否直接安装（已验证）

方案 §9.2 曾把这条列为未验证。结论：**可以**。

```
plugin_manager(install_bundle, target: "E:\dsh-plugin")
→ packageResult.exitCode 0，pnpm 报 `+ dsh-stock-desk 0.1.0 <- E:\dsh-plugin`
→ profile 下生成软链接：
   C:\Users\Administrator\.dsh\profiles\desktop\node_modules\dsh-stock-desk
     → E:\dsh-plugin   （Get-Item 显示 LinkType SymbolicLink）
```

**但软链接带来一个必须处理的后果**，见第 2 节。

## 2. 软链接导致 `@deepseek-ai/*` 解析失败（已验证，本轮最大的坑）

首次安装后：

```json
{"application":"failed",
 "diagnostic":"dsh: warning: 1 entry did not activate
   stock-desk (dsh-stock-desk): failed to import:
   Error [ERR_MODULE_NOT_FOUND]: Cannot find package '@deepseek-ai/dsh-tools'
   imported from E:\dsh-plugin\lib\tools.js"}
```

### 根因

harness 包不在 profile 的 `node_modules` 里，而在**上一层**：

```
C:\Users\Administrator\.dsh\profiles\node_modules\@deepseek-ai\   ← 实体目录，dsh-tools 在这里
C:\Users\Administrator\.dsh\profiles\desktop\node_modules\       ← 插件挂载点，没有 @deepseek-ai
```

Node 的模块解析**从导入文件的真实路径向上走**。`dsh-trellis` 是实体目录，从
`...\profiles\desktop\node_modules\dsh-trellis\lib\` 向上走一层就撞到 `profiles\node_modules\@deepseek-ai`。

而 `dsh-stock-desk` 是**软链接**，真实路径在 `E:\dsh-plugin`，向上走是
`E:\dsh-plugin\node_modules` → `E:\node_modules`，**永远走不到 `C:\Users\Administrator\.dsh\`**。

对照证据：能正常工作的 `dsh-stock-watch` **一个依赖都没声明，只 import `node:*` 内置模块**
（`dsh-stock-watch/index.js` 前 5 行全是 `node:os` / `node:fs` / `node:path` / `node:url`），
所以它从来没碰到这个问题。

### 为什么不能靠「手写一个 defineTool 替掉这个 import」

`@deepseek-ai\dsh-tools\lib\index.js:836-847` 实测：

```js
function defineTool(options) {
  const parameters = parameterSchemaSpecToJsonSchema(options.parameters);
  const outputSchema = valueSchemaSpecToJsonSchema(options.output.schema);
  const validate = (args) => validateJsonSchemaValue(parameters, args, "");
  async execute(args, exec) {
    const violations = validate(args);
    if (violations.length > 0) throw new ToolArgsError(violations);
    return userExecute(args, exec);
  }
```

它**不是恒等函数** —— 把参数规格编译成 JSON Schema 并在 `execute` 前拦截校验。
手写替代等于重实现整套 schema 编译。所以必须让解析成功，不能绕过。

### 修法

给插件目录建同层解析路径：

```powershell
New-Item -ItemType Directory "E:\dsh-plugin\node_modules" -Force
New-Item -ItemType Junction `
  -Path   "E:\dsh-plugin\node_modules\@deepseek-ai" `
  -Target "C:\Users\Administrator\.dsh\profiles\node_modules\@deepseek-ai"
```

可复现验证（**这个脚本要一直留着**，换机器/换 profile 路径后先跑它）：

```
node tools/check-resolution.mjs
→ OK @deepseek-ai/dsh-tools 导出 23 个
→ OK @deepseek-ai/schemastery 导出 1 个
→ OK defineTool 是函数
```

## 3. HMR 不会热更已激活插件的文件改动（已验证）

改完 `lib/routes.js` 与 `lib/store.js` 后，HTTP 接口**仍然返回旧代码**：

```
store.rule = fallback:homedir          ← 旧值，新代码里已改名
自选行     = 上证指数, 深证成指, 创业板指, 贵州茅台, 宁德时代   ← 旧聚合逻辑
```

修复动作是显式走一次 disable → enable：

```
plugin_manager(set_plugin, target: "include:stock-desk", enabled: false)  → application: applied
plugin_manager(set_plugin, target: "include:stock-desk", enabled: true)   → application: applied
→ store.rule = fallback:dsh-home，自选行 = 贵州茅台, 宁德时代
```

**推论（已验证范围外）：** 改宿主代码后不能只看 `fiberPhase: active` 就认为生效，
必须复验一个会变的具体值。

## 4. 宿主进程读不到 `DSH_PROFILE_DIR` / `DSH_PROFILE`（已验证）

```
GET /api/stock-desk/state
→ store.rule  = "fallback:dsh-home"
→ store.path  = "C:\Users\Administrator\.dsh\stock-desk\config.json"
```

同一时刻在 DSH 派生的 pwsh 里：

```
DSH_PROFILE_DIR = 'C:\Users\Administrator\.dsh\profiles\desktop'
DSH_PROFILE     = 'desktop'
```

结论：这两个变量**只注入给 DSH 派生的子进程，不在宿主自己的 `process.env` 里**。

同时确认 Host 现有的服务里**没有任何一个**提供 profile 目录：
`profileContext`（`Service` 目录第 1005 行）只暴露
`packageManager` / `startedBundles` / `overlays` / `telemetryDisabledEnv` 四项。

加上第 2 节的软链接条件，进程内**拿不到** profile 目录。实际落点是 `~/.dsh/stock-desk/config.json`——
属于 DSH 家目录而非 profile 目录。代价是与 profile 不同层；好处是换 profile 不丢自选。
`store.info()` 会原样带上 `rule`，界面上随时能看到命中的是哪条规则。

## 5. `sidebar.panellist` 的 `label` 必须传 thunk（已验证）

槽位目录原文（`Slots.listSubTree(root: "sidebar.panellist")` 的 catalog）：

> `label`: "Display text where the owner projects one (nav rows, tabs).
> **A thunk is re-read on every projection, so localized text follows the active
> locale without re-registering.**"

原来传的是求值后的 `T("title")`，切语言后按钮文字会僵在旧语言。已改为 `() => T("title")`，
并在 `tools/test-client.mjs` 里钉死 `typeof label === "function"`。

## 9. 客户端半边「有没有接进启动图」可以问出来（已验证）

在此之前，「插件是 active 的，但界面上什么都没有」完全没法判断：fiber 状态只说明宿主那半边起来了，
浏览器那半边要靠 boot graph 里的一条 entry 才会被加载，而这件事只有宿主问得到。

`clientModules` 服务（`Service.listService` 目录里可查）提供了两个正合适的只读方法：
`clientPath(id)` 返回某个 entry 的客户端 bundle 绝对路径，`graph()` 返回整个启动图。

于是加了一条自诊断路由 `/api/stock-desk/diag`，它通过 `ctx.get('clientModules')` 拿到服务
（可选依赖，用 `get` 而不是写进 `inject`：问不到也不影响任何正事）：

```json
{"available":true,
 "packageName":"dsh-stock-desk",
 "clientPath":"E:\\dsh-plugin\\client.js",
 "wired":true,
 "bootEntries":["@deepseek-ai/dsh-api-gateway", ..., "dsh-stock-watch", ..., "dsh-trellis", "dsh-stock-desk"],
 "note":"客户端 entry 已在启动图里：刷新浏览器页面即可加载"}
```

`wired: true` 就是「刷新页面一定有用」的硬证据 —— 这条从**推测**变成了**已验证**。

反过来说：如果 `wired: false`，那么刷新多少次都没用，问题在 `package.json` 的 `dsh.client` 声明，
不在浏览器。这两种情况的排查方向完全不同，所以值得单独一个接口。

**注意 `wired` 为 true 只保证 bundle 会被取，不保证取到后能跑起来。** 后者由第 10 节的自检覆盖。

## 10. 客户端半边的自检（已验证）

`client.js` 是浏览器模块，Node 直接 import 只会炸在没有 `window` 上。所以它能不能加载、
`apply` 能不能跑完、三个槽位注册得对不对，装完之后**完全看不到**。

`tools/test-client.mjs` 用最小桩件（`window.__ModuleLoader__`、`document`、`react`）把 factory
真跑一遍，然后断言：

1. 模块加载成功、`factory` 不抛错、`apply` 不抛错、返回 `{inject, apply}`。
2. 三个槽位的 `name` 齐全，且 **`sidebar.panellist.id === main.key`** ——
   这一条写歪的表现是「点按钮打不开自己那一页」，且不报任何错。
3. 槽位 id 等于 HTTP 路由里的 slug（跨文件交叉验证，避免「一个 slug 写歪」在很远处才暴露）。
4. `label` 是**函数**而不是求值后的字符串（理由见第 5 节）。
5. 源码里每个 `T("x")` 都有词条，zh 与 en 一一对应，且没有声明了却用不上的词条。
6. **对象字面量里没有重复键。** 同一个键写两遍是合法 JS：不报错，后者静默覆盖前者。
   本地已经踩过一次（替换本该删除的行，结果插了一个已存在的键），所以直接扫源码。
7. `locale/*.json` 的展示元数据中英齐全；`package.json` 声明指向的文件真的存在。

套件跑起来是 70 条断言。它逮到过两个**不报错的真 bug**，见下。

## 11. 两个不报错的真 bug（已验证）

### 11.1 成交额差了 10000 倍

腾讯的字段单位不统一：**成交额是万元，市值是亿元**，而这两个数字在自选表里挨着显示。

```json
{"code":"sh600519","fields":{"amount":450006,"totalCap":16604.33,...}}
```

茅台当时成交额 450006（万元）= 45.00 亿，总市值 16604.33（亿元）= 1.66 万亿。
第一版对两个字段都调了同一个 `yi()`，于是成交额列渲染成「45.00 万亿」，**差 4 个数量级，不报任何错**。

改法是把单位绑在字段名上而不是绑在调用点上：

```js
const F_UNIT = { amount: "wanYi", totalCap: "yi", floatCap: "yi", volume: "hand",
                 outer: "hand", inner: "hand", orderDiff: "hand",
                 turnover: "pct", amplitude: "pct", changePct: "pct" };
```

自检里钉着两个真实数字：`fieldText("amount", 450006) === "45.00 亿"`、
`fieldText("totalCap", 16604.33) === "1.66 万亿"`。

### 11.2 卖五档一次都不会渲染

```js
const board = levels("bids") ?? levels("asks");   // 错
```

`??` 只在左边是 `null`/`undefined` 时才评估右边，而 `levels` 返回的是 React 元素（永远非空），
所以 `levels("asks")` **根本不会被调用** —— 盘口永远只有买五档，界面上看不出少了什么。

正确写法是两侧都取再过滤空：

```js
const sides = [levels("bids"), levels("asks")].filter((x) => x !== null);
```

## 12. 把验收标准写成断言（已验证）

方案 §8 有一条硬性验收：「指数明细不得出现换手率 / 市盈率 / 市净率 / 涨跌停价 / 委比」。
在浏览器里靠肉眼点两遍是靠不住的，所以做成了机器判定。

明细按**字段是否存在**渲染（`DETAIL_GROUPS` + `fieldText` 返回 `null` 就整行跳过），
而不是写死一段模板 —— 指数的 `fields` 里本来就没有那些键，于是这条验收自动成立。

`client.js` 因此多导出一个只给自检用的 `__test`：

```js
return { inject: ["slots", "locale"], apply,
         __test: { QuoteTable, QuoteDetail, IndexStrip, fieldText, stampText } };
```

DSH 只读 `inject` 与 `apply`，多挂一个字段不影响加载。自检把两个**真实响应片段**喂进
`QuoteDetail`，把元素树摊平成文本，然后断言指数那一份不出现上述任何词、个股那一份全都出现。

## 13. 自检逮到的第三、四处 bug（已验证）

### 13.1 「距跌停」算出了负数

`到目标价还差多少` 写成 `(目标 − 现价) / 现价`，对涨停价成立，对跌停价就得出 `-9.95%`。
而「距跌停还有多少空间」显然应该是正的 `+9.95%`。两个方向必须分开：

```js
const gapUpTo   = (t) => pct(((nOr(t) - p) / p) * 100);   // 距涨停
const roomDownTo = (t) => pct(((p - nOr(t)) / p) * 100);  // 距跌停
```

### 13.2 §5.2 承诺的「位置」组整组没做

验收第 2 条要求展示 §5.2 中可得性 ✅ 的**全部**字段，方案把它分成五组，
而第一版只做了报价/量能/估值/盘口四组，位置组整组漏掉，估值组少了 `pe`，盘口少了委比。

补法：位置这一类腾讯没有现成字段，全部由已有字段算 ——
`距最高`/`距最低`/`距涨停`/`距跌停`/`较均价` 五个百分比，加一条当日区间位置条。
用相对百分比而不是绝对价差：一百块的股票和一千块的股票同样差一毛，含义完全不同。

委比同理，不取上游那个从没被证实过的字段位（`[86]`），按定义从盘口挂单量算：
`(委买量 − 委卖量) / (委买量 + 委卖量)`。

**指数天然少三行**：它的 `fields` 里没有 `limitUp`/`limitDown`/`avgPrice`，
按「字段不存在就整行不渲染」的设计，距涨停/距跌停/较均价自动不出现在指数明细里。
这不是特判出来的，是设计出来的 —— 所以自检能把三行/五行当作断言钉住。

## 14. §8 第 6 条此前一条测试都没有（已验证）

「收盘后调用同一工具，返回『已收盘 + 数据快照时刻』」这条不是不重要，
而是**没法顺手手测** —— 想手测必须等到 15:00 之后。

但收盘与否只取决于 session 对象，直接喂一个收盘时段进去就行：

```js
const CLOSED = { id: 'closed', label: '已收盘', trading: false };  // 见 lib/session.js:69
stalenessNote(CLOSED, at)  // → 注意：当前已收盘，以上为 …的快照，价格不会继续变动。
stalenessNote(TRADING, at) // → 空串
```

`test-tools.mjs` 现在钉住四条：收盘提示含「已收盘」「快照」「不会继续变动」、
交易中不加提示、拿不到 session 时按非交易处理（宁可多说一句）、
以及 `provenance` 在两种情形下分别写「未交易（已收盘）」与「交易中（午后交易）」。

## 15. 依赖实时第三方接口的断言不能这么写（已验证）

东财在连续探测后会间歇性重置连接：本项目观察到**同一轮里前几个请求成功、后几个失败**
（板块总数 496 与前 4 行都拿到了，下一个请求才 `UND_ERR_SOCKET`）。

于是四条东财相关断言会在供应商抖动时假报红，把回归门禁变成天气报告。改法有二，两条都用：

1. **判据不能用 `sources[].healthy`。** 那是三振熔断器（阈值 3），要连挂 3 次才翻，
   比现实滞后 —— 实测 `failures=2` 时它仍报 `healthy=true`，而请求已经在失败了。
2. **按结果分岔。** 取到内容就验内容，取不到就验「有没有如实说拿不到」。
   两条路都在断言真东西，且都不依赖外部服务的当日心情。

改完之后：东财掉线时五个套件仍然全绿，并在输出里明说
`（东方财富板块当前拿不到，板块断言转为验降级）`。

另外把 `test-sources.mjs` 里裸露的 `await fetchSectors(...)` 包了 try —— 它之前会**直接崩掉**，
只留一段栈，连哪条断言挂了都不说。崩掉比报红更糟。

## 16. 迁移旧自选：按自己的格式写，就等于没测（已验证）

这是本项目到目前为止最危险的一处缺陷，而且**根因在自检本身的设计**。

旧插件 `dsh-stock-watch` 把自选存在 `localStorage['stocking.config.v1']`，
真实形状抄自旧 `client.js:864` 与 `:161`：

```js
{ groups: [ { name: "分组1", symbols: [ { code: "sh000001" }, { code: "sz399300" } ] } ], updatedAt: 1760000000000 }
```

它与本插件的格式有三处不同，而每一处都会**静默**丢数据：

| # | 旧格式 | 本插件的期望 | 不改的后果 |
|---|---|---|---|
| 1 | 组的键叫 `symbols` | `items` | 每个分组迁成空数组 |
| 2 | 组只有 `name`，没有 `id` | 必须有 `id` | 每个分组被判「没有 id」而丢弃 |
| 3 | 元素是对象 `{code, buyPrice, sellPrice}` | 字符串 | 每个元素被判「无法识别」 |

三处叠加的结果**不是报错**，而是走到 `groups.length === 0` → 「已恢复出厂分组」。
用户看到的是一份看起来完全正常、但一个字都不是自己的自选。

### 为什么自检没拦住

原来的迁移测试用的是我自己写的 `{ items: ['600519', ...] }` ——

### 修复共五处

1. `symbols` 与 `items` 都认。
2. 没有 `id` 就用 `name` 推一个（`deriveGroupId`），推不出来才用序号。
3. 元素是对象时取 `.code`。
4. 报「丢了什么」改用 `describeDropped()` 读出 `code`，否则提示是

5. 买卖目标价本插件 P0 不做（方案把它放在 P2），但**必须说一声**：

## 18. 槽位注册漏了必填字段（已验证）

`shell.overlay` 是 list 槽位，它的目录里把 `id` 标成 `required: true`。而药丸那条注册写的是：

```js

```

侧边栏那条传了 `id: NS`、`main` 传了 `key`，只有这一条漏了。
**本地自检不会报错** —— 桩件的 `register` 只是把描述记下来，不做 schema 校验。
真实运行时槽位注册会失败，表现是药丸永远不出现，而且没有任何提示。

修完之后三个槽位的必填字段都有断言兜着：

| 槽位 | 种类 | 必填字段 | 值 |
|---|---|---|---|
| `sidebar.panellist` | list | `id` | `stock-desk` |
| `main` | keyed | `key` | `stock-desk` |
| `shell.overlay` | list | `id` | `stock-desk` |

另外 `sidebar.panellist.id` 与 `main.key` 必须相等，否则点按钮打不开自己那一页 ——
这一条也不报错，只是点了没反应。

## 20. 药丸点不动：shell.overlay 整层是穿透的（已验证）

`shell.overlay` 的目录原文写着：

> The layer itself is click-through — entries opt back into pointer events — so an
> occupant never blocks the app underneath.

也就是说**整层设了 `pointer-events: none`，占位者必须自己打开指针事件**。
而 `.skd-pill` 里没有这一条。后果是药丸看得见、但点不动、拖不动、也关不掉 ——
整层把指针事件全漏过去了，而且不会有任何报错或视觉异常。

修法是显式打开，并把这条件写进自检：

```css
/* shell.overlay 整层是 click-through，目录原文是 entries opt back into pointer events。
   不显式打开的话，药丸看得见但点不动、拖不动、也关不掉 —— 整层把指针事件全漏过去了。 */
.skd-pill{position:fixed;z-index:60;pointer-events:auto; ...}
```

```js
check('药丸显式打开了指针事件（shell.overlay 整层穿透）',
  /\.skd-pill\{[^}]*pointer-events:\s*auto/.test(css), '找不到 pointer-events:auto，药丸会点不动');
```

**这与第 18 节是同一类问题**：桩件不渲染、不布局、不做命中测试，
所以「点得到吗」这种事实桩件永远验不出来。凡是槽位目录里写明的运行时约定
（必填字段、指针事件、穿透层、keyed 槽位的 key 域），都得逐条抄进自检或者明确记下来。

## 23. 整页与药丸的渲染：从「只能靠肉眼」变成机器可判定（已验证）

第 1 条（整页渲染）与第 4 条（药丸显示点位 + 涨跌幅 + 涨跌家数）原本标着「只能靠用户在
浏览器右下角看」。关键突破点是 `useDesk` 的写法：

```js

```

`desk.get()` 是**调用时**取的同步快照。所以只要先把 `desk` 导出、在自检里换掉
`globalThis.fetch` 喂一份真实形状的 `/dashboard`、调一次 `desk.start()`，再调 `Pill()`，
桩件里渲染出来的就是**有数据**的样子，而不是空壳。

`client.js` 的 `__test` 因此多导出 `desk / DeskPage / DeskButton / Pill`。
断言结果（真跑的，不是构造的）：

```

      | span | skd-up | 600 | 3734.33 | span | skd-up | +0.49% | span | skd-pill-n | ↑1 ↓1
      | button | skd-pill-x | close | button | 移除 / ×
整页：276 段文字，含 上证指数 / 贵州茅台 / 3734.33 / 连板梯队那一段
按钮：button | skd-s-btn | button | svg | … | span | 行情台
```

### 桩件不只是「比真实环境宽松」，还可能「比真实环境不同」

第 21 节记的是「桩件更宽松 → 漏校验」。这一节碰到的是另一类，更难发现：

```js
const createElement = (type, props, ...children) => ({ type, props, children });
```

真实 React 把子节点塞进 `props.children`，这个桩件放在元素自己的 `children` 字段上。
展开函数组件时如果只传 `node.props`，**子节点全部丢掉** —— 组件照常返回、也不抛错，
只是里面空了。表现和「这一段真的没渲染」**一模一样**，分不出来。

我为此连着走了三条错路，每条都要记下来：

| 我的判断 | 实际原因 |
|---|---|
| `process.exit()` 截断 stdout，吞掉了 PASS 行 | **错。** `test-client.mjs` 的 `check` 通过时根本不打印（已改成照打） |
| 某个组件抛错，被 `catch { return out; }` 静默吞掉一整棵子树 | **错。** 加了错误上报后跑，`整页渲染时没有任何组件抛错` 是 PASS |
| 桩件的 `createElement` 与 React 不一致，展开时丢了子节点 | **对。** 合并 `children` 后整页从 88 段涨到 276 段，4 条红的全绿 |

一条纪律：**自检里的 `catch` 一律不许静默。** `strings()` 现在带一个 `onErr` 回调，
组件抛错会把组件名和错误信息交出来；`check` 也不许只报失败 ——
「一片空白」到底是没渲染还是没打印，必须一眼分得开。

### 顺带修掉的一个真实隐患

6 个自检文件末尾原本都是 `process.exit(fail === 0 ? 0 : 1)`。Node 写管道/文件时
`console.log` 是异步的，`process.exit()` 会截断还没 flush 的输出 —— 这**是**真实隐患
（虽然这轮的白屏不是它造成的）。已全部改成 `process.exitCode = …`，
并逐个确认 6 个套件都在 5 秒内自然退出、没有残留定时器挂住。

（`sz002739` 儒意电影、`sz000712` 锦龙股份 是用户旧插件的真实自选，
在我所有测试里从未出现过），但多出一个空的重名分组。

### 根因：`mergeGroups` 只按 id 配对

`lib/routes.js` 的 `mergeGroups` 用 `byId.get(g.id)` 找目标组。
而旧插件的分组**没有 id**，`lib/store.js:146` 规整时是按名字现推一个 ——
旧组叫「自选」，推出的 id 就是 `自选`；我这边同义组的 id 是 `watch`。
两者对不上 → 当成新组推入 → 界面上两个「自选」。

这不是「谁写错了名字」，是**配对键选错了**：id 是我这一侧的主键，
在迁移这个跨版本场景里它根本不可比，只有名字可比。

### 修法（两处，根因 + 自愈）

| 位置 | 改什么 |
|---|---|
| `lib/routes.js` `mergeGroups` | 增加 `byName` 索引，`byId.get(g.id) ?? byName.get(g.name)`；新推入的组也登记名字 |
| `lib/store.js` `normalizeConfig` | 丢弃「重名且为空」的分组，有内容的一律不碰；必须留一条 note |

`normalizeConfig` 那条是给**已经落盘**的坏数据兜底的 —— 光修根因救不了用户的现网配置。
修完实测：

```
groups: index | watch(4 只，一只没少)
store.notes: ["丢掉了和「自选」重名的那一个（它是空的）"]
```

**没有静默删除**：用户看不见的删除等同于数据丢失，所以必须留 note。
若同名组全为空则保留第一个；若有内容则内容优先，与顺序无关。

### 另一个教训：同一个错犯了第三次

`tools/test-contract.mjs` 断言「个股有盘口 ladder」在 14:56 变红。
查下去发现**断言本身错了**：14:57 起进入尾盘竞价，交易所会把盘口清掉，时段内时有时无。
（同一时刻直接打 `/quote` 反而有 `bids`，说明是间歇的，不是接口坏了。）

这已经是第三次写「依赖实时行情状态的断言」而红在断言自己身上
（前两次：涨跌停价依赖昨收、板块依赖东财可用）。改成两态断言：
有盘口就验结构，没有就验「是显式 null 而不是键消失」——后者才是客户端真正依赖的契约。
（**注意：这个两态写法下一轮就被推翻了，见 §31** —— 盘口实际有四种形态，
两态版本会在收盘后抛 TypeError 把整个套件带崩。）

第 6 轮我写过「sectors 拿到的是显式 null」。**这句是错的。**

| 契约测试 | `d.parts?.sectorsUp == null` | 都能吃，断言文案写的就是「要么是完整对象要么整段缺失」 |

所以**测试是准确的，含糊的只有我那句描述**。教训：用 `??` 兜底之后，
「缺失」和「为空」就再也分不出来了 —— 想区分就必须显式判 `in` 或 `hasOwnProperty`。

## 28. 一个不存在却用了 15 次的主题令牌（已修）

`cordis_inspect_query`（client / Theme / listTokens）给出了权威令牌表：**14 个**，
全部 `requiresLightAndDark`。而我的 CSS 里用了 `--dsw-alias-label-tertiary` —— **表里没有这个令牌**，
全文件出现 **15 次**（meta 文字、表头、代码标签、快照时刻、空态消息、数据源条、
未选中页签、药丸名字、药丸关闭按钮）。

### 为什么危险

**写一个不存在的 CSS 变量不会报错。** 浏览器只是把那一条属性丢弃，回落到继承色；
控制台一声不吭，测试也全绿。表现是这些次要文字全部继承 `.skd-root` 的
`--dsw-alias-label-primary` —— **跟主数据一样重，视觉层级被压平**。
这恰好是第 8 条要管的事：不存在的令牌谈不上「跟随主题」。

### 修法

- `.skd-root` 里定义 `--skd-dim:var(--dsw-alias-label-secondary)`，15 处统一改用它 ——
  设计系统只给了两级文字色，第三级用「两级里更暗的那级」表达，留一个可调点。
- `tools/test-client.mjs` 增加令牌白名单断言：从 `client.js` 源码里正则抓出**所有**
  `var(--dsw-*)`，逐个比对 14 个真实令牌，并断言用到的数量 ≥ 8（防止空过）。
  这类错误靠肉眼审不出来，只能靠机器列白名单。

## 31. 一个套件不是「红」而是「崩」：盘口的第五种形态

第 6 轮把 `test-tencent` 的盘口断言改成两态（有档 / null）。第 7 轮它**退出码 1 且最后一行是
`Node.js v24.21.0`** —— 这不是断言失败，是**整个套件崩了**：`bids[0].price` 抛 TypeError，
后面的断言一条都没跑到。崩掉的套件比红的套件更坏，它连「跑了几条」都不告诉你。

实测收盘后的真实形态，比「有 / 没有」两种多得多：

```
ladder = {"bids":[{"price":1324.97,"volume":1}],"asks":[]}
```

**只有买一侧，卖一侧是空数组。** 于是现在的断言不再猜形态，改成先判「有没有两侧都有货」，
再把三种情况一起覆盖：两侧满档就验买一 ≤ 卖一；否则验「字段本身在、两侧仍是数组而不是 undefined」。

这个坑前后犯了五次，每次都是**我只按当时看到的那一种形态改断言**。真正的教训不是某一版断言怎么写，
而是：**断言依赖外部状态时，要按状态空间写，不是按我看到的那一次写。**

## 34. 用户反馈三条：一条真 bug、一条布局、一条功能缺失

用户用完之后的反馈，比我自己想出来的验收条件准得多。

### ① 「涨停/炸板/跌停 都显示 — 家」——真 bug，少读了一层

宿主给的是 `overview.limitUp.today.{num,openNum,historyNum,rate}`（`today` 当日 / `yesterday` 昨日对照），
而 `LimitLadder` 写的是 `overview?.limitUp` 然后直接读 `.num` / `.openNum` —— **少读一层**，
全部取到 `undefined`，界面上三行齐刷刷「— 家」。

**为什么测试没拦住**：契约测试只验了 `limitUp` 这个键存不存在，没验再往下的字段路径；
`test-client.mjs` 的夹具形状是对的（`limitUp: { today: { num: 48 } }`），但**只给了 `num`**，
而且**没有任何一条断言在验「数字渲染出来了」**——只验了「整段缺失时不白屏」。

**这是「降级路径测了、正常路径没测」**。降级测了 10 条，正常路径一条没有。
补了 7 条：夹具换成完整真实形状，逐个数断言 47 / 19 / 22 / 71.21 / 66 都出现在文本里，
再加一条「有数据时不该出现任何一个『— 家』」。

### ② 「自选下拉框有点被挡住」——开错方向

`.skd-sr-list` 是 `position:absolute; top:calc(100% + 4px)`，固定往下开 230px。
而自选卡排在整页最下面（指数 / 涨跌家数 / 涨停 / 板块之后），**下拉直接开过视口底边被切掉一截**。

排查时先确认了不是 CSS 裁剪：`.skd-card` / `.skd-card-h` / `.skd-card-b` 上**都没有 overflow**
（唯一有 `overflow:hidden` 的是 `.skd-d`，那是详情面板）。

改法：打开时量一次输入框在视口里的位置，下半屏就往上开（`data-up="1"` → `bottom:calc(100% + 4px)`）。
量不到（自检环境没有 `window`）就保持往下，与改动前一致，不会更糟。

### ③ 「这些不能点击吗」——功能确实缺

连板梯队里的股票名原本是 `r.stocks.map(s => s.name).join(" ")`，**纯文本，没有点击处理**。
它们本来就带 `code`，接上 `onPick` 就能开详情 —— 之前白白浪费了。

**但直接接 `setSel` 会点出一片空白**：`QuoteDetail` 是在自选列表里按 code 找的，
而梯队里的股票绝大多数不在自选里。所以加了一条路径：点了不在自选里的股票就现拉一次 `/quote`，
详情优先用它，关掉时一并清掉。

断言不写成「有没有 `onClick`」（那种断言永远绿），而是**真调一次 handler，看它交出的 code 对不对**：
2 行梯队各 1 只 → 2 个可点元素，依次点下去应得到 `sz002889,sz000576`。

### 这一轮的教训

三条里两条是「我自己没想到要验」的：**正常路径没测**、**用户在真实视口里的布局没测**。
我一直在验「拿不到数据时会不会白屏」，却没验「拿到数据时数字对不对」；
一直在验「渲染出多少段文字」，却没验「它落在屏幕的哪里」。

另外两条断言是**我写错、不是代码错**（按钮数写成 `>=3`，实际夹具算出来就是 2；
又拿只点了一次的计数去比按钮总数）。数字要按夹具算，不能凭手感。

## 35. 用户第二轮反馈：详情面板被遮挡 + 边框贴边

「自选点了后，被遮挡了，感觉是不是边框有点太极限了呀，而且也没滚动条」——
三个症状，两个根因。

### ① 没有滚动条 → 整页容器自己不滚

`.skd-page` 原本只有 `display:flex`，**没有高度约束、也没有 overflow**。
外层 `main` 槽位容器不给滚动条，于是超出视口的内容永远够不着 —— 详情面板又正好在整页最下面。

改：`.skd-page{height:100%;box-sizing:border-box;overflow-y:auto;overscroll-behavior:contain}`。

`height:100%` 在父容器高度不确定时会退化成 `auto`，也就是回到改动前的行为，
不会更糟；父容器高度确定时它才生效 —— **这是个不会把情况变坏的改法**。

### ② 边框「太极限」→ 详情面板与卡片边框贴在一起

`.skd-card-b{padding:6px 0}` —— **横向内边距是 0**。
表格靠单元格自己的 `padding:4px 10px` 与边框拉开距离，所以看着正常；
而 `.skd-d`（详情面板）只有 `margin-top:10px`、没有横向外边距，
**它自己那圈边框就直接压在卡片边框上**，两条线贴在一起。

改：`.skd-d{margin:10px 10px 6px}`，与表格那 10px 对齐。

### 教训

这两条都是**纯布局问题，Node 里的桩件一条也测不出来** —— 没有排版引擎，`height:100%`
算出来是几、两条边框相距多少像素，全都要真浏览器才有答案。

能做的只有把「修复还在不在」锁住：加两条正则断言盯住
`.skd-page` 的 `overflow-y:auto` 和 `.skd-d` 的 `margin:10px 10px`，谁删了它们就会红。
**测不了「画得对不对」，至少测得了「上次那个修复有没有被删掉」。**

而这两条我一开始都没想到要验 —— 我验的全是「数据对不对」。用户看的是**像素**。

## 36. 用户第三轮反馈：移除没反应 + 没有 K 线图

### ① 「点击移除按钮没效果」——保存是好的，是界面没刷新

**先证伪「保存失败」**：直接 POST `/config` 去掉一只，返回 `ok=true`、列表已变，
重新 GET `/state` 也是新的 —— **落盘一直是好的**。

真因在这一行：

```js
const cur = data?.config ?? meta?.config ?? null;   // 错
```

`save()` 更新的是 `meta.config`，而 `cur` **优先读 `data.config`** ——
`data` 是轮询回来的快照，**盘后 60 秒一轮**。于是点完一分钟内界面纹丝不动，
看着就像没生效。改成 `meta?.config ?? data?.config`（`meta` 既来自 `/state`
也来自保存响应，永远是较新的那份）。两处都有这个写法，一起改了。

**另一个旁证**：动手前自选是 4 只，实测时只剩 3 只 —— 说明用户此前某次移除**其实成功了**，
只是当时没看出来。**「没效果」和「没有立即效果」在用户眼里是同一件事。**

### ② 没有 K 线图 —— 我把方案里的一条漏做了

`grep kline client.js` → **0 处**。方案 §5.2 白纸黑字写着「日/周/月 K + MA」，**我压根没做**。
详情面板只有数字，走势图完全没有。

**顺带挖出一个更严重的**：`lib/tencent.js` 里**一个 K 线函数都没有**，
`market.js` 是 `guarded('em', ...)` —— **单源，无后备**。而方案 §6 定的分工是
「K 线主源腾讯 `ifzq.gtimg.cn`、东财后备」。实测当天东财限流，`/kline` 直接 500，
个股和指数**都取不到**。这不是「没做」，是**做了但只有一条腿**。

修法：
- `lib/tencent.js` 新增 `fetchKline`，返回形状与东财对齐（`date/open/close/high/low/volume`）。
  腾讯一行只有 6 列，成交额/振幅/换手率它不给，**一律置 null，不拿别的数顶上**；
  涨跌幅由前收推出来，注释里标明是派生值。
- `lib/market.js` 的 `rawKline` 改成双源：**日/周/月走腾讯，分钟线走东财**。
  两边能力正好互补 —— 腾讯只给日周月，东财给分钟。谁挂了都还有图看。
- 接口会多给一根（要 6 给 7）。**留着它给第一根当昨收再截到 limit**，
  否则每张图的头一根涨跌幅都是 null。

**实测的坑**：指数没有复权概念，腾讯对指数返回的键是 `day` 而不是 `qfqday` ——
取键要按「`qfq`+周期」再退回「周期」两段找，顺序不能反。

### 客户端图表

内联 SVG，不引图表库：插件没有构建步骤，`client.js` 是直接交给 `__ModuleLoader__` 的，
多一个依赖就多一条加载路径。柱 + 线就画完了。

**画图部分抽成纯函数 `klineChart(cs, code)`** —— 组件里那条路要等 fetch 回来才走到，
而自检的桩件不跑 effect，图表最容易崩的地方（空数组、单根、缺字段）就永远测不到。
抽出来之后可以直接把真实 candles 喂进去。加 23 条断言：正常 120 根 / 1 根 / 2 根 / 空数组 ×
（不抛错、画出内容、蜡烛根数对、**坐标里没有 NaN**、三条均线都在），
再加 volume 整列 null、close 整列 null、MA20 不足期必须是 null 而不是硬凑。

**NaN 那条是必须显式查的**：SVG 会静默忽略非法坐标，画出来是空白，不报错。
`allFieldsMissing` 时 `Math.min(...[])` 是 `Infinity`，坐标会算成 NaN —— 已兜底。

### 教训

漏做的东西不会因为我没测它就消失。**我该在交付前拿方案 §5.2 那张表逐行对一遍「做了没」**，
而不是只对「做过的那些做得对不对」。这一条漏了整整 36 节才被用户发现。

## 37. 移除还是没反应 —— 第 36 节那次的诊断只对了一半

用户复测后反馈「还是没移除」。回看 §36，我当时**只证明了宿主端存得进去**，
并没有证明「用户点的那颗按钮 → 表格」这条链路上每一环都对。

**真因在渲染层，不在保存层**：

```js
h(QuoteTable, { list: parts.watchlist?.items, ... })   // 错
```

表格渲染的是 `parts.watchlist` —— **那份轮询快照**，不是配置。
§36 我改的是 `cur`（配置的读取顺序），**但表格根本不吃 `cur`**，所以那一改等于没修。
用户点完，配置确实存进去了，表格却还照着 60 秒前的快照画。

**正确的分工是：配置决定「显示哪几只」，快照只提供「数字」。**

```js
const quoteOf = new Map((parts.watchlist?.items ?? []).map((q) => [q.code, q]));
const watchRows = (watchGroup?.items ?? []).map((code) => quoteOf.get(code) ?? { code, name: code });
```

刚加进来、快照里还没有的股票，先用代码占位，下一轮自然补上 —— 加和删都立刻可见。

`QuoteDetail` 的回落查找也得一起改：**不能再回落到 `parts.watchlist`**，
刚删掉的那只在快照里还在，拿它会把已经移除的行又画出来。

### 为什么这条测试以前测不到

`DASH_FIXTURE.config` **根本没写 `groups`**，于是 `watchGroup` 恒为 `null`，
自选表在自检里从来没被渲染过 —— 一个没被渲染过的组件，怎么改都不会变红。

补上 `groups` 之后才写出这条回归：**造出错位** —— 配置里删掉一只、快照里留着它，
断言表里立刻看不到那只。这正好是用户点完移除后那一瞬间的真实状态。

### 顺带：让失败可见

`removeCode` 原本没有 `catch`，`save` 抛错会被静默吞掉，**表现和「按钮坏了」一模一样**，
用户无法区分「没生效」和「没保存」。现在存不上会直接把原因写到界面上。

### 教训

**「服务端做对了」不等于「用户看到对了」。** 上一次我在服务端验证通过就下了结论，
中间隔着渲染层、轮询周期、组件取值三跳。定位这种问题时，
要顺着「用户动作 → 状态变更 → 渲染取值 → 数据来源」从头走一遍，
而不是在离用户最远的那一端证明它对。

## 38. 补分时图 —— 顺手抓出一个「不报错的错」

用户确认移除已正常，接着问「k线图怎么没有分时」。

### 接口形状

腾讯 `web.ifzq.gtimg.cn/appstock/app/minute/query?code=sh600519`，
一行四个字段：**`HHMM 价格 累计成交量(手) 累计成交额(元)`**。
后两个都是**累计值**，不是当分钟的增量 —— 这一条决定了两个算法：

① **量能柱必须用相邻两行相减**。直接拿第 3 列画，出来是一条单调上升的斜线，
   看着像「成交量一直涨」，其实是累计量的形状。自检里专门断言「序列不得单调不减」。

② **均价不能简单用「累计额 ÷ 累计量」** —— 见下。

只取到 15:00。接口收盘后多给 25 行盘后竞价（个股 267 行 vs 指数 242 行），
而行情软件的分时图一律画到 15:00，多出来的会把横轴拉长、图形挤扁。过滤后 242 点，
正好是 09:30–11:30 + 13:00–15:00。

### 均价：两种算法，其中一种只对个股成立

第一版用「累计成交额 ÷ (累计成交量 × 100)」，个股上**看着完全正确**：
09:30 算出 1322.50，与该分钟价格一模一样。**于是我以为对了。**

接上指数才发现：

| | 末价 | 额量法 | 量价加权法 |
|---|---|---|---|
| sh600519 贵州茅台 | 1324.97 | **1336.29** | 1336.47 |
| sh000001 上证指数 | 3730.92 | **16.44** ← 错 | 3716.99 |

指数差了 200 多倍。原因是**指数的成交额/成交量得到的是「平均每股价格」**
（约 15 元，即全市场股票的平均股价），**不是指数点位**。

两种算法在个股上只差 0.18（视觉上不可区分），所以**统一用量价加权**：
个股和指数都对，也不必再判品种。

**这个错不会报任何异常** —— 均价线会贴着坐标轴底部画成一条直线，
既不影响其余渲染，也不产生 NaN。**只有把指数也拉一遍才会暴露。**

### 回归断言

```
指数分时的均价与点位同量级（额量法在此会算出个位数）
  avg > price * 0.8 && avg < price * 1.2
```

个股那条只断言「均价与现价相差 5% 以内」，**上证指数那条才是真正拦住这个 bug 的**。

### 分时图的纵轴必须关于昨收对称

这是它和 K 线图最大的区别：K 线按最高最低铺满，分时**要以昨收为中心上下取同一个幅度**。
否则涨 1% 和跌 1% 会被画成一样高，「今天到底涨了还是跌了」这个最该一眼看出的信息反而丢了。

自检直接解析 SVG 坐标来锁这条：昨收基准线必须落在纵轴正中（y≈90），
且价格线 y 值的中位数必须与基准线重合（容差 2）。**画歪不会抛异常，只能这样测。**

### 教训

**「在一种输入上验对了」不等于「对了」。** 个股测通就收工，指数就会带着错上线。
这次的检查项很便宜 —— 把同一段逻辑喂给每一类标的各跑一遍。
上一节 K 线漏做也是同一类问题：只验了做过的，没验该做的。

## 39. 图表「看不懂」—— 根因是整张图上一个数字都没有

用户反馈「分时的 k 线图有点简单呀，我有点看不懂」。回看第一版：

**图上有曲线、有均线、有量能柱，但没有任何一个数字。** 最高多少、现价多少、
这一刻比昨收高几个点，全靠眼睛比划。**这不是「简单」，是缺了读数的入口。**

补了六样，按对可读性的贡献排序：

1. **左右刻度 + 横向网格**（贡献最大）。左列价位、右列涨跌幅，5 条等分线。
   分时的右刻度是判断「对称」最直接的证据 —— 昨收那一行必须正好是 `+0.00%`，
   自检里就是这么断言的，一条断言同时校验了对称性和刻度换算。
2. **面积填充**。沿价格线走一圈回到基准线闭合，**同一个路径画两遍**，
   分别挂「基准线以上」和「基准线以下」两个 `clipPath` —— 一次就得到涨红跌绿两块，
   不用把曲线在基准线处切段。`clipPath` 的 id 用实例计数器保证唯一（同页可能挂多张图）。
3. **十字光标**。鼠标移到哪就报哪一根/哪一分钟的价格、均价、涨跌幅，图例跟着走。
   没有它只能看个大概形状。
4. **最新价圆点**。收盘后一眼看到落在哪，不用顺着线找末端。
5. **K 线的四价读数**（开/高/低/收 + 涨跌幅），悬停时报那一根，不悬停时报最后一根。
6. **分时横轴补上 13:00**。中午休市那 90 分钟是接在一起画的，
   只标 09:30 / 11:30 / 15:00 会让人把上午下午看成连续两段。

### 光标换算必须实测元素宽度

`viewBox` 宽 720，但 svg 被拉伸到容器宽度，两者不相等。
按 720 直接换算会整体偏移，**而且窗口越宽偏得越多**：

```js
const r = ev.currentTarget.getBoundingClientRect();
const vbX = ((ev.clientX - r.left) / (r.width || 1)) * CH.W;
```

换算本身抽成了 `chartPick(n)` 纯函数。**不能为了拿这个换算去调一次完整的图表函数** ——
那等于每动一下鼠标就重建整棵元素树。自检直接测它：第 0/100/241 格中心各自对应自己的下标，
左边界外、右边界外、负数坐标、0 个点四种情况一律给 `null`（返回 0 会让光标死死卡在第一格）。

### 桩件与真实 React 的一处不同

`text` 元素的文本在桩件里挂在 `node.children`，真实 React 在 `props.children`。
断言取值要按桩件的来 —— 这是「桩件可能比运行时更宽松，也可能不同」那一类，
第一次写就踩到了，六条断言同时红。

—— 459 条断言 / 6 个套件 / 全绿。

## 40. 「被遮挡」的定位与缩放平移

用户反馈两件事：「k 线图能不能滑动/缩放」和「我看也有一些被遮挡了」。

### 遮挡：顶部那条刻度被画布切掉了

不是布局问题，是 SVG 的坐标问题。刻度文字**骑在网格线上**（`y = 刻度y + 3.5`），
而最上面那条网格线在 `y = 0` —— 11px 的字有约 8px 伸到画布外，
被 svg 直接裁掉半个字。

修法是给画布上方留 `MT = 12` 的边距，所有纵向坐标整体下移。

**这类问题不会报错，也不会少画元素**，元素在 DOM 里好好的，只是画在了看不见的地方。
所以断言只能这么写：`CH.MT >= 9` —— 直接锁住「字号的一半必须在画布内」这个几何条件。

同一个坑还在三处重复：`chartYTicks` 的网格线、`chartCross` 的竖线、
两个 `clipPath` 的裁剪矩形。**修一处必须搜同类其余处**，这是第 4 次栽在这条上了。

### 缩放平移：改视窗，不重新请求

宿主一次给 250 根，本地切窗口显示。**每滚一下滑轮就发一次请求既卡又浪费，
拖动时根本跟不上。**

- **Ctrl + 滚轮缩放**：以光标所在比例 `frac` 为锚点 —— 缩放后让光标底下那一根停在原地。
  不做锚点的话每缩一次图都往一边跑，想放大看某根得反复「缩一下、拖回去」。
- **按住拖动平移**：拖过的像素换算成根数。
- 不按 Ctrl 时一律放行，页面该滚就滚，**不抢滚轮**。

### 必须用原生 wheel 监听器

React 的 `onWheel` 挂在根节点上，Chrome 对根节点的 wheel 监听默认 `passive`，
里面调 `preventDefault()` 不生效 —— **结果图放大了、整页也跟着滚了**。
所以用 `useRef` 拿元素、`addEventListener('wheel', fn, { passive: false })`。

### 差点写出一个 Rules of Hooks 违规

切窗口的代码本来放在 `if (st.err) return` **之后**，而它里面要用 `useEffect` 挂滚轮监听。
那是条件调用 hook —— `st.err` 一变（比如某次请求失败）React 立刻抛
「Rendered fewer hooks than expected」，**而且报错位置和真正的原因隔着十万八千里**。

规矩：**所有 hook 必须在第一个 `return` 之前**。切片和滚轮监听因此都提到了前面。

### 两条断言写错了，是断言错不是代码错

① `span = end - size` 是错的 —— 起点是 `max(0, end - size)`，所以显示根数是 `min(size, end)`。
   在 `end = nAll` 时两者恰好相等，**所以大部分用例都过了，只有一个红**。
② 平移断言里我用 `size` 当分母算每根宽度，但 `size` 是缩放后的窗口宽度。

**一个只在边界上才成立的错误公式，会在边界用例上以「代码看起来错了」的形式暴露。**
先怀疑断言。

—— 473 条断言 / 6 个套件 / 全绿。

## 41. 「Ctrl+滚轮没效果」——两个叠在一起的错，还有一个是方向反了

用户装了缩放平移后回来说「Ctrl+滚轮怎么没有效果呀？按住拖动也没有」。

### 错一：功能只做了 3/4，而默认落在没做的那一个上

`useState("min")` —— 默认页签是分时。而滚轮监听和拖动入口都写着：

```js
if (period === "min" || nAll === 0) return undefined;   // 滚轮
if (period === "min" || nAll <= vSize) return;          // 拖动
```

**两个功能在默认页签上被代码保证失效。** 而提示文字是无条件写的
「Ctrl+滚轮缩放 · 按住拖动平移」—— **说得到，做不到。**

我的判断是「分时是固定 242 点，没有可平移的余地」，所以只给 K 线做了。
但我把这个判断**留在了代码里，没有告诉用户**。

修法不是加个牌子写明「这里不能缩放」，而是**让分时也能缩放**：
分时和 K 线本来就可以共用同一套窗口机制（分时的一「根」是一分钟），
数据源从 `st.minute.points` 取即可。缩放后原来那四个固定时刻
（开/午/午后/收）会失真，改成标当前视窗的首末时刻。

### 错二：缩放方向反了，而测试跟着一起写错

「放大」应该让每根变宽 = **视窗根数变少**。我写的是：

```js
const raw = size * (deltaY < 0 ? ZOOM_STEP : 1 / ZOOM_STEP);   // 反了
```

向上滚代码执行 `size *= 1.25` —— 根数变多，那是**缩小**。

**这一条叠加上错一**：分时默认就是全天 242 点，向上滚想「放大」时被上限 `cap = nAll` 夹住，
`min(max(242 × 1.25, 20), 242) = 242` —— **一个点都不变，表现就是「滚了没反应」。**

**而我的测试断言写的是「向上滚一格变 150 根」并 PASS 了。**
测试照抄了我的错误假设，什么都没锁住 —— **测试成了代码的镜像。**

正确断言只有一条能拦住这种错：**「视窗已经全天时，向上滚仍能放大」** ——
它描述的是用户能观察到的现象，不是我脑子里那套换算。

### 补上了能看见交互层的自检

原来的桩件里 `useState` 返回 `[值, () => {}]`、`useEffect: () => {}`，
所以**「点了没反应 / 拖了没反应 / 滚了没反应」这类 bug 一个都测不出来**。
而最近四个 bug 全在这一层。

补了一个最小 hook 运行时：`setState` 触发重渲染、effect 真跑、ref 挂到元素上、
`addEventListener` 记得下 `opts`。于是可以这样断言：

```
PASS 交互：滚轮监听注册为 passive:false（否则拦不住页面滚动）
PASS 交互：默认是分时，全天 242 点都画出来
PASS 交互：分时上 Ctrl+向上滚真的放大了（这就是用户说「没效果」的那一步）  → 242 → 194
PASS 交互：不按 Ctrl 时不拦截滚轮（页面该滚还得滚）
PASS 交互：切到日K后画的是 120 根（默认视窗）  → 120
```

**「提示与能力必须一致」也变成了一条断言**：分时页签上必须也写着缩放提示 ——
因为现在它真的能缩放了。

### 搭这个运行时踩的坑

① 第一次跑直接 `Maximum call stack size exceeded` —— 树里出现了回边。
   现在遍历带 `WeakSet`，环只会被计数、不会炸掉整个文件。
   （栈溢出比断言失败难查得多：它把后面所有用例一起埋掉。）
② 新开的 factory 实例**没跑 `apply`**，词条没注册，`T("kDay")` 原样返回 `"kDay"`,
   于是「找不到日K页签」看起来像组件坏了，其实是测试环境没搭好。
③ `bind` 可能早于 `register` 被调用，词表要**懒查**，不能当场取值。

`test-sources`（打真实行情的联网自检）红了，3/3 复现。

### 42.2 板块宇宙为什么不用腾讯

### 42.10 用户报「点上去按钮变全白」—— data-d 拿到了 CSS 类名

**现象**：刷新后能看到格子了，但点维度 tab 时格子「变全白」。

**根因**：`dir()` 返回的是 **CSS 类名** `skd-up` / `skd-down` / `skd-flat`（它给 `className` 用的），
我把它当属性值塞进了 `data-d`：

```js
"data-d": dir(x.changePct),        // → data-d="skd-up"
```

而 CSS 判断的是 `[data-d="up"]` —— 永远匹配不上，于是：

- 底色 `color-mix` 不生效 → 退回 `bg-layer-1`，**浅色主题下就是白色**
- 大数字的 `color:var(--skd-up)` 不生效 → 红绿也没有

且「涨停最多」那个 tab 当时硬编码了 `"up"`，**反而是有色的**。切 tab 时一边有色一边全白，
看起来就像「点一下被点白了」，实际是那两个维度的颜色从来没生效过。

**修法**：单列 `dirKey()` 只返回 `up` / `down` / `flat` 三个纯值供属性使用，并加 `[data-d="flat"]`；
底色浓度 13% → 18%，补 `:focus-visible` 描边。

**为什么之前的断言没锁住**：我只写了「格子里有数据-d 这个属性吗」，
没写「它取哪几个值」。补了两条值域断言：

```
板块格子：data-d 只取 up/down/flat 三个纯值（不是 CSS 类名）   → up,up,up,up
板块格子：涨最狠维度第一个格子是 up（会画成红色底）             → up
板块格子：跌最狠维度的格子是 down（会画成绿色底）               → down
板块格子：涨停维度也走同一套值域（有涨停就是 up）                → up
```

**同类排查**（第 42.9 条纪律：修完一类 bug 的一个实例必须搜同类其余实例）：
扫了全部 `"data-*":` 取值表达式，其余都是字面 `"0"`/`"1"` 或布尔表达式，
没有第二处把返回类名的函数当属性值用。

自检：`test-client` **258 通过 / 0 失败**（新增 4 条）。


### 42.11 「选谁谁白」的真因：拿 brand-primary 填底

**用户补充**：不是格子，是维度切换按钮（涨最狠 / 跌最狠 / 涨停最多）——「选谁谁白」。

```css
.skd-btab[data-on="1"]{background:var(--dsw-alias-brand-primary);border-color:transparent;color:#fff}
```

这个主题**只有 14 个令牌，没有 on-brand 前景色令牌**（没有 label-inverse / on-brand 这类）。
现有代码里 `brand-primary` 一律只当线条用 —— `.skd-tab[data-on="1"]` 只改
`border-bottom-color` 与文字色，从不拿它填底。我造了个填充胶囊 + 硬编码 `#fff`，
等于在赌一个不存在的令牌：品牌色在大面积填充时偏浅，白字压上去就是白底白字。

**修法**：跟 `.skd-tab` 同一套语汇 —— 强调色只用于描边，文字仍取 `label-primary`：

```css
.skd-btab[data-on="1"]{background:var(--dsw-alias-bg-layer-2);border-color:var(--dsw-alias-brand-primary);
  color:var(--dsw-alias-label-primary);font-weight:600}
```

**同类排查**又抓到一处同病：`.skd-btn[data-primary="1"]`（设置页的「保存」）也是
`brand-primary` 填底 + `#fff`，一并改成把 `label-primary` 与 `bg-base` 反过来用
（浅色主题得深底浅字、深色主题得浅底深字，两种主题对比度都成立）。

**为什么之前的断言没锁住**：主题令牌那条只验了「没用不存在的令牌」，
没验「令牌之间怎么搭配」。补四条源码级回归闸：

```
样式里不硬编码 #fff / #ffffff                      → 无
选中的维度 tab 文字色取 label-primary               → background:bg-layer-2;border-color:brand-primary
选中的维度 tab 不拿 brand-primary 填底              → 同上
主按钮靠 label-primary/bg-base 反色取对比度          → border-color:transparent;background:label-primary;color:bg-base
```

**教训（已补进本项目纪律）**：能用令牌不等于能随便搭配。
一个主题没有 on-brand 前景色，就意味着品牌色**只能**当线条，不能当底色。

自检：全套 **529 通过 / 0 失败**（`test-client` 262）。


### 42.12 用户报「总页数像是股票数量」—— 同花顺匿名只开放前 5 页

**现象**：下钻面板的页码看着不对，怀疑把股票数量当成了总页数。

**查下来的真实情况（分两步）**：

第一步，确认换算公式本身没错 —— 银行 3 页/42 只、厨卫电器 1 页/9 只、汽车零部件 14 页/280 只，
`ceil(上游页数 × 每页只数 / 20)` 与实际完全一致。

第二步，发现**上游页数根本翻不到**。逐页探测：

```
301558 概念  page 1 len=73452 正常 · page 2 正常 · page 3/4/5 正常 · page 6 len=192 存根
881126 行业  page 1..5 正常（20 行/页）                     · page 6 len=192 存根
```

那 192 字节的存根正文是：

```html
<script src="//s.thsi.cn/js/chameleon/chameleon.1.7.min.1792399.js"></script>
<script>location.href="//upass.10jqka.com.cn/login?redir=https://q.10jqka.com.cn"</script>
```

**是登录墙。** 边界很硬：`page/5/` 正常，`page/6/` 起一律存根。
绕行尝试各一次全部失败：裸请求 / +Referer / +Referer+Accept / 伪造 `hexin-v` cookie ——
四种都是 192 字节存根，而 page 5 照常 73631 字节。

**后果**：概念最多看前 50 只（5 页 × 10），行业最多前 100 只（5 × 20）。
所以「机器人概念 1/62 页」这句是**承诺了 62 页、实际第 3 页就没数据** ——
用户看着那个大数字，自然会怀疑它是股票数量。

**修法（改的是「不许骗人」，不是绕）**：

1. `FREE_PAGE_LIMIT = 5` 常量，`page/6/` 起**不再发请求**（发了只拿存根，白跑还可能被限流）
2. `totalPages` 夹到免费上限：概念最多 3 页、行业最多 5 页
3. 超限时返回 `truncated: true` + `freeStocks`（概念的 50 / 行业的 100）
4. 前端在面板头部明说「同花顺免费只开放前 5 页，更多需登录」
5. 页码标签补上单位：`1 / 3` → **`1 / 3 页`**（孤零零的 `1 / 62` 太容易被读成只数）
6. 解析器把登录墙与「板块没有成分股」分开（`loginWall` 标志），
   否则界面上会把「看不到」说成「没有」

**修复前后对比（实机）**：

| 板块 | 修前 | 修后 |
|---|---|---|
| 机器人概念 | 1/62 页（翻到第 3 页即空） | **1/3 页**，标「仅开放前 50 只」 |
| 专精特新 | 1/63 页 | **1/3 页**，标「仅开放前 50 只」 |
| 汽车零部件 | 1/14 页（page 6 起登录墙） | **1/5 页**，标「仅开放前 100 只」 |
| 银行 | 1/3 页 | 1/3 页（未触上限，不变） |
| 厨卫电器 | 1/1 页 | 1/1 页「全部 9 只」 |

**这意味着什么**：最初承诺的「下钻看到该板块所有股票」**只能做到前 50 / 100 只**。
这是同花顺的上游限制，没有替代源（腾讯无成分股接口、东财 clist 被按路径拦截）。
这条必须让用户知道，不能假装做全了。

**自检**：`test-boards` 36、`test-contract` 97（含 4 条夹取断言）、`test-client` 263，
全套 **537 通过 / 0 失败**。


### 42.13 删掉「涨停最多」tab，把涨停/炸板/跌停/连板梯队改成可下钻的格子

**用户反馈**：「这个板块（涨停卡）是不是和『涨停最多』模块冲突了？感觉描述的是同一个东西，
你应该把涨停最多按钮删除，然后把涨停、炸板、跌停、连板梯队搞成可以下钻的，也变成格子的形态。」

确认冲突成立：板块格子的第三个维度「涨停最多」来自 `block_top`（今天涨停家数最多的板块），
而上面那张涨停卡讲的是「今天涨停的都是谁」——**同一批股票的两个入口**，看着像两回事。

**改动一：删掉「涨停最多」维度。** 板块格子只剩涨最狠 / 跌最狠。
`boardRank.limit` 仍在接口里返回（agent 工具还在用），只是不再有 UI 入口。

**改动二：涨停卡变成格子，四样东西都能点。**

| 格子 | 数字来源 | 点进去 |
|---|---|---|
| 涨停 | 同花顺 `overview.limitUp.today.num`（46） | `limit_up_pool` 46 条，带连板高度/首封时间/涨停原因 |
| 炸板 | 同花顺 `overview.limitUp.today.openNum`（20） | `open_limit_pool` 20 条 |

| 首板 | 推算 = 涨停 − 连板 | **不可点**（推算值没有对应名单） |

**为什么跌停要用本地扫描**：同花顺没有跌停池。`limit_up_pool` / `open_limit_pool` 之外，
又试了 13 个候选路径名（`limit_down_pool` `down_limit_pool` `limit_down` `down_pool`
`limit_down_list` `limit_up_pool_down` `down_limit_up_pool` `limit_down_stock`
`limit_down_num` `drop_limit_pool` `limit_pool` …）**全部 404**。

**为什么涨停/炸板不直接用本地扫描**：同花顺的池字段更全（连板高度、首封时间、涨停原因），
对短线更有用。而它的口径与自扫描不同（同一天：同花顺 46/20，自扫描 50/24，差在 ST 与
个别漏项如 `杰克科技`），所以**每个格子的数字必须取它自己那份名单的来源**：

```
涨停格子 46 家 → /pool?type=limitup 返回 46 条    ✓ 对得上
炸板格子 20 家 → /pool?type=broke   返回 20 条    ✓ 对得上
跌停格子 27 家 → /pool?type=limitdown 返回 27 条  ✓ 对得上（且与 limitPools.limitDown 一致）
```

混着取就会变成「格子写 22 家、点进去 27 条」——用户会当成算错了。跌停格子因此标了
「本地扫描」小字，说明它与行情软件的 22 家不是同一口径。

**踩到的坑**：同花顺池接口的 `limit` 上限是 **200**，传 300 直接
`status_code=-1, msg="limitmust be less than or equal to 200"`（报错里连空格都没有）。

决定出不出那两列。

**自检**：`test-client` 268（新增 18 条涨停格子断言，含「点连板高度只出该高度的股票」
与「首板不可点」）、`test-contract` 118（新增 `/pool` 三个池的自洽断言），

**未验证**：浏览器里的实际观感 —— 槽位查询证明不了渲染，需要刷新后由用户确认。

### 42.15 跌停格子是红色的 —— 方向不能从数量推

**用户反馈**：「但是他是红色的这个格子」（跌停那一格）。

**根因**：`poolTile` 的底色写成 `dirKey(count)`，而 `dirKey` 判的是「数值正负」。
跌停 27 家是个**正数**，于是被判成「涨」→ 红色。**数量是正数不代表行情是涨的**，
这两件事没有关系。同一个错误也让涨停（红）与跌停（红）看着一样。

**修法**：方向由格子语义显式给定，`poolTile(key, label, count, sub, kind, tone)`：

| 格子 | tone | 颜色 |
|---|---|---|
| 涨停 | `up` | 红 |
| 炸板 | `warn` | 警示色（既不是涨也不是跌，别让人误读成红/绿） |
| 跌停 | `down` | 绿 |
| 首板 | `flat` | 中性（推算值不该带方向） |

**补断言时又抓到一个更严重的 bug**：改参数时把 `kind`（池子类型）那一格挤掉了，
`poolTile("limitup", ..., "up")` 实际上把 `"up"` 传给了 `kind` ——
`data-d` 变成 `undefined`，**而且点下去会拿 `kind="up"` 去请求一个不存在的池**，
三个格子全部点不出数据。

这就是「断言要落在用户能观察到的现象上」的价值：如果只断言「格子存在」「有 onClick」，
这个必现的点击失败一条都抓不到。补的是值域断言：

```
涨停格子：涨停是 up（红）                → up
涨停格子：跌停是 down（绿），不是红        → down
涨停格子：炸板是 warn（警示色），不冒充涨跌  → warn
涨停格子：首板是 flat（中性）             → flat
```

另给 `[data-d="warn"]` 补了样式（底色 15% 警示色 + 数字同色）。

自检：全套 **572 通过 / 0 失败**（`test-client` 273）。


### 42.16 首板可下钻 + 术语问号

**用户两问**：「首板为什么点不进去？」「炸板是什么意思？能不能来个小问号圆圈，鼠标指上去给我描述一下。」

**① 首板以前不可点的理由，其实是错的。**
当时判断「首板是 `涨停 − 连板` 的推算值，没有对应名单」。但名单是能算出来的：
**首板 = 涨停池 − 连板梯队里的代码**。
实测严丝合缝：涨停池 46 条 − 连板梯队 11 个代码 = 35 只，**11 个连板代码全部出现在涨停池里**，

它的 `field` 掩码里没带这个字段。所以改走「池子减梯队」，不依赖那个字段。

**② 术语问号。** 新增 `Hint` 组件（`<span class="skd-hint">?</span>` + `title`），
挂在每个格子名称后面。用 `span` 而不是 `button`：它不该进 Tab 序，只是提示，

覆盖的术语与说明：

| 术语 | 说明 |

| 涨停 | 当日收盘价达到涨停价、并且封住的个股家数 |
| 炸板 | 盘中曾经触及涨停价、但到收盘又没封住的个股。数越大说明当天涨停越不牢靠，追高容易吃面 |

### 42.19 详情从「下方」改成「左右分栏」

**用户反馈**：「点开股票后详情在下方出现有点累，使用上还得滑动有点累，你看看能不能左右栏的效果呀」。

**改法**：新增 `splitView(detail, children)` —— 有 detail 时渲染成
`[左栏：名单 | 右栏：明细与 K 线]`，没有 detail 时列表独占整行（不会凭空留一条空白列）。
右栏 `position:sticky` 跟随滚动，窄屏（<720px）退回上下堆叠。

**三处都改了**：板块成分股下钻、涨停/炸板/跌停/首板/连板池下钻、自选卡（同一个毛病）。

**踩到的三个坑（都是自检抓的，不是猜的）**：

1. **`SplitView` 不能写成 React 组件**。自检的 `walk` 只遍历 `children`、不展开子组件函数，
   包成组件后 `.skd-split` 根本不出现在被测树里，「到底有没有分栏」就验不到。
   改成直接返回元素的普通函数，输出就进了父级树。

2. **`children` 必须展开（`...list`）**。写成 `h(Fragment, null, children)`（整个数组当一格）
   时，React 会自己拍平，但 `walk` 不会往数组里钻 —— 整块名单从被测树里消失，
   表现为「一页渲染 0 只」。**界面上其实是好的**，这个坑只在自检里现形。
   所以这条断言的价值不在抓 UI bug，而在保证自检还能看见真实结构。

3. **`selQ` 踩了 TDZ**。为了给自选卡判断「有没有右栏」，把 `selQ` 提成了变量，
   但插在了 `watchRows` 声明之前 → `Cannot access 'watchRows' before initialization`。
   这类错误只在整页真的渲染时才炸，纯函数自检发现不了。

**还修了一条假通过的断言**：原来写的是 `includes('skd-d')` 判右栏有没有内容，
而 `skd-drill-body` 里也含 `skd-d` —— 恒真。改成直接看右栏的子元素里有没有 `StockPeek`。

断言：

```
板块下钻：没点开股票时是单栏（不凭空留一条空白列）
板块下钻：点开股票后变成左右两栏            → 1
```

### 42.20 「涨最狠点进去卡在正在取数…」—— 排查与兜底

**用户反馈**：「涨最狠点进去，怎么卡在：正在取数…呀」。

**先逐层排除（都是实测）**：

| 检查 | 结果 |
|---|---|
| 后端 `/board?code=881174&kind=thshy` | HTTP 200，**1~3ms**（首次 148ms） |
| 连打 8 次 | 8/8 成功，无一次卡住 |
| 四个数据源健康度 | 全部 `healthy=true failures=0` |
| `/dashboard` | 176ms，`boardRank.up=10`，`errors={}` |
| 系统代理是否会拦 127.0.0.1 | **不会**：`ProxyOverride` 含 `127.*` 与 `localhost` |
| 浏览器跑的是不是新代码 | **是**：把 `sidebar.panellist` 的 `order` 临时改成 77 当构建标记，Slots Inspect 读回来正是 `77` |

**结论**：后端没问题、代码是新版、网络路径没被拦。剩下的唯一可能就是
**浏览器侧的 `fetch` 把请求挂住了** —— 而 `fetch` 默认**没有超时**，
于是界面永远停在「正在取数…」，既不报错也不恢复。

**根因没能完全定位**（连接为什么被挂住，我在服务端看不到）。
但这类「无限转圈」本身是个必须修的设计缺陷，不管触发原因是什么。

**修法**：

1. `api()` 加 15 秒 `AbortController` 超时。超时后抛
   `请求超时（15s）：/board`，而不是永远转圈。
   > 之前还有一次同源事故：这条 `api` 的超时改动第一次其实**没写进文件** ——
   > 脚本在 `writeFileSync` 之前就 `process.exit(1)` 了，但前面几行已经 `console.log('ok')`。
   > 所以「脚本说 ok」不等于「文件改了」。后来靠「`T("timeout")` 词条声明了却没人用」
   > 这条断言才暴露出来。
2. 取数失败时给**重试按钮**，点击自增 `tries`，`tries` 在取数 effect 的依赖数组里，
   所以能真的重跑。
3. 构建标记 `order: 77` 留在代码里并写了注释 —— 以后再遇到「改了没生效」，
   先查 Slots Inspect 的 order 就能立刻分辨是缓存还是代码。

断言：

```
api() 带 AbortController 超时（否则挂住就永远转圈）
超时错误用词条而不是硬编码文案
取数失败时给了重试按钮
重试会真的重跑 effect（tries 进依赖数组）
```

自检：全套 **609 通过 / 0 失败**（`test-client` 296）。

**下一步**：如果刷新后还卡，15 秒内会变成一条明确的报错。把那句话发我，

### 42.22 「板块的股票详情卡在正在取数」的真因：裸 6 位代码从来没查到过

**用户反馈**：「板块的股票详情还是卡在：正在取数」。

**这是一个藏了好几轮的真 bug，不是超时。** 逐层查下来：

```
/quote?codes=300911     → items=0  missing=["300911"]
/quote?codes=sz300911   → items=1  ✓
/quote?codes=600519     → items=0  missing=["600519"]
/quote?codes=sh600519   → items=1  ✓
```

**裸 6 位代码全部查不到。** 根因在 `market.quotes()`：

```js
const key = `q:${list.sort().join(',')}`;
const map = await cache.get(key, TTL.quote, (signal) => rawQuotes(list, ...), opts);
for (const code of list) {
  const f = map.get(code);          // ← 拿【原始】代码去查
```

而 `fetchQuotes` 内部先 `normalizeCodes` 再请求，返回的 Map 是以**归一化后**的代码
（`sz300911`）为键的。于是 `map.get("300911")` 永远是 undefined，全落进 `missing`。

**为什么藏了这么久**：自选股一直是带前缀的写法（`sh600519`），所以从来没踩到；
板块成分股（同花顺页面给的）恰好是裸 6 位，于是「点开个股详情」永远是空的。
顺带也解释了为什么腾讯那边必须带前缀 —— 实测 `q=300911` 它直接不返回这一条。

**修法**：`quotes()` 开头先归一化，返回的 `code` 统一成归一化写法，
另带一个 `requested` 保留调用方原本的字符串（前端要靠它对回手里的值）。
认不出来的写法仍然如实进 `missing` —— 这一点差点被我改丢，
是 `test-market` 的「非法代码不抛错，进 missing」那条红回来才想起来的。

**同一个症状还有第二层原因**：`StockPeek` 里

```js
if (!st.q) return h(Msg, { text: T("loading") });   // ← 「还在加载」和「拿不到」被混成一件
```

接口返回空时它也显示「正在取数…」，永远转。已拆成
`phase === "loading"` → 正在取数；`!st.q` → 「拿不到这只票的报价（可能腾讯不覆盖它的代码）」。

**验证**：

```

002543   items=1  万和电气 深主板 8.03
600519   items=1  贵州茅台 沪主板 1324.97
920100   items=1  三协电机 北交所 26.49     ← 北交所也通了
板块成分股前 3 只报价：3/3
```

### 42.27 持仓（成本/份额/盈亏）+ 刷新间隔 + 价格监控通知

**用户要求**：「自选能不能填成本价、持仓份额、今日盈亏、持仓盈亏，支持手动修改；每 10 秒自动刷新；
设置监控价格（低/高），到价通过电脑通知我」。

**① 配置层**（`lib/store.js`）

新增两个 map，**不塞进 `groups[].items`**：

```js
positions: { "sh600519": { cost: 1200.5, shares: 100 } }
alerts:    { "sh600519": { low: 1000, high: 1500 } }
ui.pollSec: 10
```

为什么不改 `items`：它是 `string[]`，迁移、合并、agent 工具三处都按纯代码列表用，
改成对象要一次性打断三处且旧配置全得迁。单独一张 map 既能带附加信息，又完全向后兼容。

规整规则（**不编默认值**）：

- 只认正的有限数。成本填 0/负数、份额为 0 → 该字段直接丢，
  否则界面上会出现「成本 0 元、盈利 100%」这种假数字
- 低价 ≥ 高价是明显填反了 → **保留用户填的值**（不静默改），补一条 note 提醒
- `pollSec` 只认白名单 `[3,5,10,15,30,60]`；传 2 会回落 10，避免客户端每秒打一次接口

**② 刷新间隔**

`createDesk` 里原来只认宿主给的 `pollMs`（交易中 3 秒、休市 60 秒）。改成：

```js
const sec = Number(snap.data?.config?.ui?.pollSec);
const wait = Number.isFinite(sec) && sec > 0 ? sec * 1000 : (snap.data?.pollMs ?? 5000);
```

用户设了就以用户为准，没设才回落宿主默认。

**③ 持仓表**

列：名称 / 现价 / 成本价 / 份额 / 今日盈亏 / 持仓盈亏 / 低价提醒 / 高价提醒。
后四列是可编辑输入框。

- 今日盈亏 =（现价 − 昨收）× 份额
- 持仓盈亏 =（现价 − 成本）× 份额

**输入框刻意用非受控（`defaultValue` + `onBlur`）**：页面每 10 秒轮询一次，
受控输入会被新快照覆盖掉正在输入的内容 —— 输到一半数字被重置，比不能输入更让人抓狂。
回车直接提交，清空即删除该字段（而不是存成 0）。

**④ 价格监控与电脑通知**

用浏览器 `Notification` API。**只在「跨过阈值的那一刻」弹**：
记住每只票上一次的状态（low / high / null），只有状态变了才弹。
否则价格停在阈值下方时每 10 秒弹一次，用户第一件事就是关掉通知。
状态放 `useRef` —— 它不该触发重渲染，也不该被快照覆盖。

权限状态三态：`granted`（已开）/ `denied`（被拒，按钮上写清楚要去浏览器站点设置里允许）/
`unsupported`（环境不支持）。不静默失败。

**⑤ 一个自检踩到的坑**：通知标题原本写成
`T(now === "low" ? "notifyTitleLow" : "notifyTitleHigh")` ——
自检的「声明了却用不上」规则只认 `T("字面量")`，三元里的键名它看不见，
于是这两个词条被误报成多余的。改成先算 `const title = now === "low" ? T("notifyTitleLow") : T("notifyTitleHigh")`。

**实测**：配置往返（写入 → 读回）`positions` / `alerts` / `pollSec` 全部保住，`notes=[]`。
验证用的假数据**已清理**，不留假持仓在你配置里。

```
成本/份额/低价/高价四个输入框都在
输入框带出已保存的值（成本,份额,低价,高价）  → 1200,100,1200,1400
改成本价会回传 positions 且只改这一项
清空高价会删掉该字段而不是存成 0
没填持仓时给出填写提示
```

**用户反馈**：「怎么整个行情台都变黑了呀，啥也看不到了」。

| 检查 | 结果 |
|---|---|
| 槽位注册 | `stock-desk` 仍 `active`，order 77 → `apply` 跑完了，不是模块加载失败 |

**最可疑的一处**：`Notification.permission` 的读取。原代码把它放在 `useState` 的初始化函数里：

```js
React.useState(() => typeof Notification === "undefined" ? "unsupported" : Notification.permission)
```

SecurityError**。它抛在 useState 的初始化里，整个组件直接挂掉 → 用户看到的就是「一片黑」，

**更要紧的是改了工程习惯**：加了一层错误边界。

```js
class DeskBoundary extends React.Component {
  static getDerivedStateFromError(err) { return { err }; }
  render() { return this.state.err
    ? "行情台渲染出错：<原因>"          // 有字可读
    : this.props.children; }            // 正常透传
}
```

`main` 槽位现在注册的是 `DeskSafe`（带边界的壳），不是裸的 `DeskPage`。
**以后任何渲染异常都会显示成一行能找到原因的文字，而不是黑屏。**

用 class 是因为错误边界只能靠 `getDerivedStateFromError` 实现，没有 hook 版本。
测试桩里原来没有 `React.Component`，已补上 —— 桩件就该照实覆盖 API。

断言：

```

错误边界：正常时直接透传子节点
main 注册的是带错误边界的外壳 DeskSafe，不是裸面板 → panel:DeskButton main:DeskSafe overlay:Pill tab:SettingsTab
```

### 42.31 「今天才买，今日盈亏怎么是 −46」—— 基准日选错了

**用户反馈**：半导体设备ETF易方达（sz159558）今天才买，今日盈亏显示 −46.00，质疑算法。

**反推验证（完全对得上）**：

```
现价 0.89，涨跌 −4.92%  →  昨收 ≈ 0.936
今日盈亏 =(0.89 − 0.936)×1000 = −46.00   ← 原公式
持仓盈亏 =(0.89 − 0.905)×1000 = −15.00   ← 用户的实际盈亏
```

**根因**：今日盈亏用的是 `(现价 − 昨收) × 份额`。这个定义只有在
**「昨天收盘就持有这些份额」**时才对。今天才买的仓位，基准应该是个人的成本价，
按昨收算等于替一只跌了 5% 的票记一笔**根本没发生过的亏损**。

**修法**：`positions` 增加一个显式标记 `todayBuy`。

```json
"positions": { "sz159558": { "cost": 0.905, "shares": 1000, "todayBuy": true } }
```

- `todayBuy === true` → 今日盈亏 =(现价 − 成本价)× 份额（与持仓盈亏一致）
- 否则 → 今日盈亏 =(现价 − 昨收)× 份额（沿用「持有过隔夜」的口径）

编辑态在成本价格子里多一个「今买」勾选框；只读态勾过的会在成本价旁显示「今买」小标签。
勾选框带 `title` 解释为什么需要它。

**为什么不做成自动判断**：我们没有昨仓/今仓的拆分，只能用「成本 vs 昨收」猜 ——
而本例中成本 0.905 **低于**昨收 0.936，任何基于大小关系的启发式都会猜错。
所以交给用户显式标注，不猜。

**你的这行数据**：勾上「今买」后，今日盈亏会从 **−46.00 变成 −15.00**，与持仓盈亏一致。

断言：

```
另有一个「今买」勾选框
今买的仓位：今日盈亏按成本价算（+826.00），不是按昨收（−74.00）
今买的仓位在成本价旁标「今买」
```

自检：全套 **658 通过 / 0 失败**（`test-client` 324）。


### 42.32 「点不了今买」—— 布尔值被当成非法数字

**用户反馈**：「点不了呀今买」。

**根因**：勾选框的 `onChange` 传的是布尔 `true`，而草稿编辑的唯一入口只认数字：

```js
const n = Number(String(true).trim());   // NaN
if (raw === "" || !Number.isFinite(n) || n <= 0) delete one[field];   // 永远走这一支
```

于是「加上又立刻删掉」，勾永远打不上。

**修法**：

1. 布尔先单独处理：`true` → 写入，`false` → 删除
2. **把这段逻辑从 DeskPage 的闭包里抽成纯函数 `applyDraftEdit(draft, kind, code, field, raw)`** ——
   原来它埋在 onClick 闭包里，缺陷无法被测试直接调用，只能靠用户点一遍才发现。这与之前
   「`api` 超时改动没写进文件」是同一类问题：**逻辑藏在测不到的地方**。
3. 顺带修了一个更粗暴的行为：非法数字（比如粘贴 `abc`）原本会**删掉已保存的值**，
   一次输错就把之前填的成本抹了。改成「非法值一律无视，保留原值」；
   只有显式清空（空字符串）才删除字段。

断言（6 条，直接打 `applyDraftEdit`）：

```
勾上今买：草稿里真的写进了 todayBuy=true
勾上今买：原有的成本与份额没被弄丢
取消勾选：todayBuy 被删掉而不是存成 false
数字输入仍然正常写入
清空数字会删掉该字段而不是存 0
非法数字被忽略（保留原值）
```

自检：全套 **664 通过 / 0 失败**（`test-client` 330）。


### 42.33 今日盈亏不归零 + 加刷新倒计时

用户反馈两件事：①「自选的今日盈亏我看怎么没清零」；②「能不能在栏里面有一个计时器导数？要不然我都不知道刷新没有」。

#### ① 不归零的根因：行情日期从没跟今天比对过

实测取证（2026-10-20 09:09，未开盘）：

```json
{ "code": "sz002739", "price": 8.27, "prevClose": 8.14, "changePct": 1.6, "time": "20261019161439" }
```

`time` 是**昨天 16:14**。开盘前腾讯返回的就是上一交易日的收盘快照，而代码里直接拿 `(现价 − 昨收) × 份额`
当今日盈亏，于是昨天的 +26.00 今天继续显示 —— 看起来就是「没清零」。

**修法**：

- 新增 `quoteDate(f)` 从 `time` 取日期（`20261019161439` → `2026-10-19`），`todayKey()` 取北京时区今天。
- 行情日期 ≠ 今天 → **今日盈亏显示「—」**，并在名称旁打「昨收」标签（虚边框，样式弱化）。
- 持仓盈亏不受影响 —— 它是成本基准，跨日依然正确（实测仍算出 −15.00）。

顺带把「今买」也改成带日期：`todayBuy` 从布尔改成 `YYYY-MM-DD`。
只存 `true` 的话昨天勾的今天还生效，今日盈亏就永远退化成持仓盈亏。
旧数据（`true`）在 `normalizeConfig` 里一次性迁移成当天日期。

#### ② 刷新倒计时

`createDesk` 的轮询间隔在界面上原本完全不可见，静态页面看不出是活的。

新增 `RefreshMeter`（自选卡右上角）：`● 刷新 8s · 09:09:31`

- 左边是距下次刷新的秒数，每秒减一 —— **数字在动就说明定时器活着**
- 右边是这批数据的到达时间（客户端自己记的，不用服务器的 `at`，避免时钟偏差导致倒计时一开始就是负数）
- 超时钳到 0，不显示 `-3s`（那会让人以为坏了）

`nextRefreshSec(lastAt, pollSec, nowMs)` 抽成纯函数，边界可测。

#### ③ 顺带修掉的一批「未开盘即 500」

早上跑测试暴露了同一类问题的多个实例 —— **所有数据源都把「今天还没开盘」当成故障**：

| 接口 | 症状 | 修法 |
|---|---|---|
| `/ladder` | 抛 `status_code=10003 尚未开盘` → 500 | `fetchLadder` 捕获 → 返回 `[]` |
| `/pool?type=firstboard` | 500 | `fetchPool` 捕获 → `{total:0, items:[]}` |
| `/board` | 500（熔断器抛的，在函数内部 try 之外） | `market.boardStocksSafe` 再兜一层 |
| `parts.sectorHeat` | 进 `errors` | **未修**，见下 |

错误对象现在带 `thsCode` / `thsMsg`，`isNotOpenYet(err)` 统一识别
`尚未开盘 / 非交易日 / 暂无数据 / 集合竞价`。注意「集合竞价期间无实际成交，数据暂不刷新」
是 09:15–09:30 的常态，最初的正则漏了「集合竞价」这个词，导致 `/board` 仍然 500。

**遗留**：`parts.sectorHeat`（涨停板块榜）在集合竞价期间仍会进 `errors`，板块涨停格子空着。
`/dashboard` 本身 200、其余分块正常，属于可接受的降级，未做假的空数据填充。

#### ④ 测试改成「不依赖挂钟」

早上跑测试一片红，全是因为断言默认「市场今天已经有数据」。这类断言是**构造上就会误报**的：

- 新增 `expectData(name, cond, extra)`：未开盘时打印 `SKIP <名字>（未开盘，今天还没有数据）`，计入通过但不冒充已验证。
- 用 `/dashboard` 的 `session.trading` 判断（`/state` 上没有 `session` 字段）。
- 涉及：涨停家数 > 0、分时有点、分时均价、板块涨停榜、`breadth.amount` 为正值、
  `sectorHeat` 是数组、首板池条数、行业板块数量 = 90（未开盘实测只有 51 条且涨跌幅全 0）。

自检：**642 通过 / 0 失败 / 24 条因当前未开盘跳过**。
所有接口（`/state` `/dashboard` `/board` `/pool` `/quote` `/kline` `/minute`）均 200。

#### ⑤ 这一轮踩到的两个新坑（已记入教训）

1. **`\d` 在 JS 字符串字面量里是非法转义，会被吃掉**：补丁脚本里的 `/^\d{8}/` 写进文件后变成
   `/^d{8}/`，`quoteDate` 永远返回 null，今日盈亏也就永远不清零。改用 `[0-9]` 绕开。
   全库扫过一遍同类写法，其余 `\d` 都正确（写成了 `\\d`）。
2. **`RegExp` 带 `g` 时 `test()` 会推进 `lastIndex`**，紧接着的 `replace()` 从中间开始找、直接落空。
   批量改写断言时因此「报告改写了 0 条」却又不报错。判断存在性要用不带 `g` 的正则。
